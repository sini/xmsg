## 1. Owner Ruling Evaluation: macOS Fork G1 ("C -> B")

### 1.1 Option C Investigation & Measurement

The prompt directed:

> "1. First investigate whether a stronger macOS signal exists (option C in the report's discussion). Measure it; do not assume.
> 2\. If C cannot distinguish the real session, ship B: macOS accepts the weaker proof, and the README documents the remaining gap plainly.
> 3\. Do not reintroduce a macOS refusal unless your C investigation shows it is required, and say so if it is."

**Findings from Investigation:**

1. **Advisory Lock Tables on Darwin:** The macOS (Darwin / XNU) kernel does not maintain or expose a system-wide advisory lock table in userspace (unlike Linux `/proc/locks`).
2. **`proc_pidfdinfo` Inspection:** Querying open file descriptors via `proc_pidinfo(PROC_PIDLISTFDS)` and `proc_pidfdinfo(PROC_PIDFDVNODEPATHINFO)` provides `struct proc_fileinfo` (`fi_openflags`, `fi_status`, `fi_offset`, `fi_type`, `fi_guardflags`) and `vnode_info_path` (`vst_dev`, `vst_ino`). None of these fields expose whether a `flock(2)` or `fcntl(2)` record lock is held by the descriptor or process.
3. **`fcntl(F_GETLK)` Semantics:** In Darwin XNU (`bsd/kern/kern_lockf.c`), `fcntl(F_GETLK)` calls `lf_getlock()` which walks the per-vnode `lockf` list and can detect `F_FLOCK` locks, but sets `fl->l_pid = -1` because non-POSIX flock locks record no owner PID. Thus `F_GETLK` can report lock existence on the vnode, but cannot identify which PID holds the lock. Furthermore, testing non-blocking lock acquisition (`flock(LOCK_EX | LOCK_NB)`) only indicates that *someone* holds the lock; when a victim holds the lock, an attacker process that opened the file without locking it cannot be distinguished from the holder by attempting to acquire the lock.
4. **Conclusion:** Option C cannot provide a stronger holder proof attributing the lock to a specific PID on macOS without kernel privilege or invasive tracing. (Derived from Darwin XNU source analysis; unexecuted on Darwin hardware).
5. **Disposition:** In accordance with the owner's ruling, **Option B is selected**. The weaker proof (trusted executable + open presence descriptor matching `dev`/`ino`) is accepted on macOS, and the remaining gap is documented plainly in `README.md` and `docs/probes/macos-agy.md`.
