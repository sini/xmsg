## 1. Problem & Context

Claude Code (and other agent harnesses) running on a single host can communicate via native model tool calls (`ListAgents`, `SendMessage`), but outside scripts, CI jobs, or peer processes cannot list live running sessions or deliver messages into a running session without consuming expensive model turns.

`xmsg` v1 provides a fast, lightweight HTTP bridge running on the local host that:
1. Lists live interactive agent sessions by scanning the local session directory.
2. Delivers messages directly into a target session's Unix inbox socket without consuming a model turn.
3. Authenticates and sanitizes envelope sender names and bodies to prevent sender impersonation or tag-injection attacks.

## 2. Unit U1 Scope & Boundaries

### In Scope for U1
- Standalone Rust binary crate `xmsg` built with `tokio` (multi-threaded async runtime), `axum` (HTTP routing), `serde`/`serde_json` (serialization), `clap` (CLI argument parsing), and `tracing` (structured diagnostics).
- The `serve` CLI subcommand with flags:
  - `--listen` (env `XMSG_LISTEN`, default `127.0.0.1:7787`)
  - `--host-label` (env `XMSG_HOST_LABEL`, default system hostname)
  - `--sessions-dir` (env `XMSG_SESSIONS_DIR`, default `~/.claude/sessions`)
  - `--max-body` (env `XMSG_MAX_BODY`, default `65536` bytes / 64 KiB)
- Four HTTP endpoints under prefix `/v1` and health check:
  - `GET /healthz`
  - `GET /v1/sessions` (with optional `?cwd=` and `?status=busy|idle` query filters)
  - `GET /v1/sessions/{ref}`
  - `POST /v1/sessions/{ref}/messages`
- Envelope and Transport layer implementations meeting all §5.2 specifications:
  - Envelope: sanitizes `from` (collapses whitespace, strips `"`, `<`, `>`, and Unicode categories `Cc`, `Cf`, `Cs`, `Zl`, `Zp`, trims whitespace). Prefixes `xmsg@<host-label> · `. Truncates the whole resulting string to 64 Unicode characters using character-safe scalar/grapheme iteration.
  - Body Sanitization: replaces every `<` beginning `/?cross-session-message` (case-insensitive) anywhere in the body with `<\`.
  - Body Logging Ban: Request bodies are strictly forbidden from being logged. Stderr logs only request id, session id, sanitized `from`, byte count, and outcome.
  - Transport: typed `InboxLine` serialized strictly with `serde_json::to_string` + `\n`. Never built with string formatting or concatenation.
  - Delivery: direct `UnixStream` write to `messagingSocketPath` with a 5-second timeout on connect and write.
- Gating Oracle (§7a) executed via `cargo test`:
  - `proptest` encoding property suite + fixed edge case tests.
  - `registry` fixture test suite (live PID, dead PID -> 410, reused PID via mismatched `procStart` -> 410, malformed JSON, unread `.key`).
  - End-to-end integration test against a stand-in `UnixListener` verifying 200, 202, 400 (`bad_request`, `bad_sender`), 404 (`not_found`), 409 (`ambiguous`), 410 (`gone`), 413 (`payload_too_large`), 502 (`inbox_unavailable`), and 504 (`inbox_timeout`).
- Packaging:
  - Root `flake.nix` with `rustPlatform.buildRustPackage`, `cargoLock.lockFile`, and `doCheck = true`.
  - `LICENSE` (MIT), `.gitignore`, and `README.md`.
  - `ci/flake.nix` consuming `gen-harness.lib.mkCi` with `{ gen.ci.rootSurface.entry = "not-owed"; gen.ci.agentsMd.sheet = "not-owed"; }`, `testModules = ./tests;`, and an extra module or check building the root package with `doCheck = true`.
  - Note: No root `default.nix` is created, avoiding collisions with `gen-harness` root-surface checks.

### Out of Scope for U1
- v2 features: SQLite reply database (`xmsg.db`), reply tool (`xmsg mcp`), long-polling `/v1/messages/{id}/replies`.
- v3 features: Antigravity and pi adapters (`register.sock`, `agentapi`, extensions).
- System configuration: home-manager module and systemd units in `nix-config`.
- Remote repository publishing (`github:sini/xmsg` stays local only).

### 3.2 Data Models & Wire Types

#### Session Registry Model (`registry.rs`)
Parsed from `~/.claude/sessions/<pid>.json`:
```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct SessionFileEntry {
    pub pid: u32,
    pub session_id: String,
    #[serde(default)]
    pub name: Option<String>,
    pub cwd: String,
    pub status: String,
    pub kind: String,
    #[serde(default)]
    pub entrypoint: Option<String>,
    #[serde(default)]
    pub version: Option<String>,
    pub started_at: u64,
    pub updated_at: u64,
    pub proc_start: String,
    pub messaging_socket_path: String,
}
```

Exposed in HTTP API as `Session` (§4):
```rust
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
pub struct Session {
    pub session_id: String,
    pub name: Option<String>,
    pub pid: u32,
    pub cwd: String,
    pub status: String,
    pub kind: String,
    pub entrypoint: Option<String>,
    pub version: Option<String>,
    pub started_at: u64,
    pub updated_at: u64,
}
```
*Invariants:*
1. `messaging_socket_path` and any token/key are strictly omitted from the external API model.
2. `GET /v1/sessions` accepts query parameters:
```rust
#[derive(Debug, Deserialize, Default)]
pub struct SessionsQuery {
    pub cwd: Option<String>,
    pub status: Option<String>,
}
```

#### Inbox Transport Models (`inbox.rs`)
Wire transport line sent to the Unix socket (deriving both `Serialize` and `Deserialize` to enable §7a proptest round-trip validation):
```rust
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct InboxLine {
    pub r#type: String, // "user"
    pub message: InboxMessage,
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct InboxMessage {
    pub role: String, // "user"
    pub content: String,
}
```

HTTP Request & Response:
```rust
#[derive(Debug, Deserialize)]
#[serde(deny_unknown_fields)]
pub struct SendMessageRequest {
    pub from: String,
    pub text: String,
}

#[derive(Debug, Serialize)]
pub struct DeliveryResponse {
    pub session_id: String,
    pub from_name: String,
    pub bytes: usize,
}
```

Error Format (§5.4):
```rust
#[derive(Debug, Serialize)]
pub struct ErrorResponse {
    pub error: &'static str,
    pub detail: String,
}
```
Mapped HTTP statuses:
- 400: `bad_request` (malformed JSON, empty `text`, unknown field)
- 400: `bad_sender` (`from` empty after sanitization)
- 404: `not_found` (no session matches `{ref}`)
- 409: `ambiguous` (multiple sessions match `{ref}`)
- 410: `gone` (entry stale: pid dead or `procStart` mismatch)
- 413: `payload_too_large` (body exceeds `--max-body`)
- 502: `inbox_unavailable` (socket connect / write error)
- 504: `inbox_timeout` (connect / write exceeded 5 seconds)

### 3.3 Core Logic

#### Registry Liveness & Resolution
1. On every request, `registry::list_sessions(sessions_dir, query)` scans the directory without caching.
2. For each `<pid>.json`:
   - Checks `/proc/<pid>/stat` on Linux.
   - Extracts field 22 (`starttime` in clock ticks) by finding the final closing paren `)` and splitting whitespace.
   - Validates that `procStart == entry.proc_start`.
   - If `/proc/<pid>` does not exist or `procStart` mismatches, logs and skips the entry as stale/reused.
   - Skips malformed files and strictly avoids opening any `*.key` files.
   - Applies optional query filters:
     - `cwd`: matches if session `cwd` equals or is a subpath of query `cwd`.
     - `status`: matches `entry.status == query.status`.
3. `registry::resolve_session(sessions_dir, ref)`:
   - Scans all files on disk matching `{ref}` by `session_id`, `pid`, or `name`.
   - If one or more candidate entries match `{ref}` on disk:
     - Check liveness on each matching candidate.
     - If all matching candidates fail liveness (dead PID or `procStart` mismatch), return `Error::Gone` (HTTP 410).
     - If multiple live candidates match by name: return `Error::Ambiguous` (HTTP 409) listing the candidate session IDs.
     - If exactly one live candidate matches: return the resolved `(Session, messaging_socket_path)`.
   - If no candidates exist on disk at all: return `Error::NotFound` (HTTP 404).

#### Envelope Sanitization & Transport
1. **`from` sanitization:**
   - Collapse consecutive whitespace characters into a single space.
   - Strip `"`, `<`, `>`, and Unicode categories `Cc`, `Cf`, `Cs`, `Zl`, `Zp`.
   - Trim leading and trailing whitespace.
   - If empty after sanitization, reject with HTTP 400 (`bad_sender`).
   - Prefix `xmsg@<host-label> · `.
   - Truncate the whole resulting sender string to at most 64 Unicode characters using character-safe iteration:
     ```rust
     let capped: String = format!("xmsg@{host_label} · {sanitized}")
         .chars()
         .take(64)
         .collect();
     ```
2. **Body sanitization:**
   - Case-insensitive search for every `<` that begins `/?cross-session-message` anywhere in the body, replacing `<` with `<\`.
3. **Transport line assembly:**
   - Envelope text: `<cross-session-message from-name="{from_name}">\n{sanitized_body}\n</cross-session-message>`.
   - Wire line: `serde_json::to_string(&InboxLine { r#type: "user".into(), message: InboxMessage { role: "user".into(), content: envelope } })? + "\n"`.
   - Single-line newline-delimited output.
4. **Socket Write:**
   - Connects to Unix stream socket at `messaging_socket_path` with a 5-second timeout.
   - Writes the line with a 5-second timeout.
   - On success returns HTTP 202 (`DeliveryResponse`).
   - Connection/write failure returns HTTP 502 (`inbox_unavailable`); timeout returns HTTP 504 (`inbox_timeout`).
5. **Diagnostics & Logging Invariant:**
   - Each HTTP request logs exactly one structured line to stderr: request ID, resolved `session_id`, sanitized `from`, byte count, and outcome.
   - **Message bodies are never logged under any circumstances.**

## 4. Acceptance Oracles (§7a Gating Oracle)

All gating checks are implemented as automated tests run by `cargo test` and enforced during Nix build via `doCheck = true`:

1. **Property-Based Encoding Tests (`proptest`):**
   - Validates arbitrary `from` and `text` strings.
   - Asserts:
     - Output contains exactly one `\n`, positioned as the final byte.
     - Output successfully parses as valid JSON into `InboxLine` (`serde_json::from_str::<InboxLine>`).
     - Inner envelope content contains exactly one opening tag `<cross-session-message ...>` and one closing tag `</cross-session-message>`.
     - Whole `from_name` length in chars is <= 64 and starts with `xmsg@`.
   - Fixed edge cases:
     - Body containing literal `</cross-session-message>`.
     - Body containing mid-body `</cross-session-message>` injection attempts.
     - Body containing NUL bytes, `\r`, and Unicode line separators (`U+2028`).
     - 200-character `from` string (asserts truncation to <= 64 chars without splitting code points).

2. **Registry Fixture Tests:**
   - Creates a temporary directory containing:
     - Live entry: uses current test runner PID and reads actual field 22 from `/proc/self/stat`.
     - Dead PID: uses an unallocated high PID (e.g. `4194300`).
     - Reused PID: uses current test runner PID with mismatched `procStart`.
     - Malformed JSON file.
     - `.key` file with poisoned content (ensuring it is never opened).
   - Asserts:
     - Only the live entry is returned by `list_sessions`.
     - Dead and reused entries are filtered out of listing.
     - Resolving the dead PID returns `Error::Gone` (HTTP 410).
     - Resolving the reused PID returns `Error::Gone` (HTTP 410).
     - Resolving a non-existent PID returns `Error::NotFound` (HTTP 404).
     - The `.key` file is never opened or read (verified via access checks).

3. **End-to-End HTTP Server Integration Test:**
   - Starts a stand-in `UnixListener` on an ephemeral Unix domain socket.
   - Creates temporary session entries pointing to that socket (and stale entries for dead PIDs).
   - Binds an `axum` test server to an ephemeral TCP port (`127.0.0.1:0`).
   - Asserts:
     - `GET /healthz` returns `200 OK` with `{"status":"ok","sessions_dir":"ok"}`.
     - `GET /v1/sessions` returns `200 OK` with live sessions array, correctly filtering on `?cwd=` and `?status=`.
     - `GET /v1/sessions/{ref}` returns `200 OK` with session object.
     - `POST /v1/sessions/{ref}/messages` returns `202 Accepted` and verifies exact bytes received by UnixListener.
     - `POST` with dead PID returns `410 Gone`.
     - `POST` with unknown field in JSON returns `400 Bad Request`.
     - `POST` with empty `text` returns `400 Bad Request`.
     - `POST` with empty `from` after sanitization returns `400 Bad Request` (`bad_sender`).
     - `POST` with duplicate matching session names returns `409 Conflict`.
     - `POST` with non-existent ref returns `404 Not Found`.
     - `POST` exceeding `--max-body` returns `413 Payload Too Large`.
     - `POST` when UnixListener is closed returns `502 Bad Gateway` (`inbox_unavailable`).

## 5. Packaging & CI Details

1. **Root Flake (`flake.nix`):**
   - Uses `nixpkgs` input.
   - Defines `packages.<system>.default` using `pkgs.rustPlatform.buildRustPackage`.
   - Points `cargoLock.lockFile = ./Cargo.lock`.
   - Sets `doCheck = true` so the entire §7a test suite runs during `nix build .#default`.
   - Exposes `devShells.<system>.default` with `cargo`, `rustc`, `clippy`, `rustfmt`, and `rust-analyzer`.
   - **No `default.nix`:** Deleted to prevent collisions with `gen-harness` root-surface checks.

2. **CI Flake (`ci/flake.nix`):**
   - Consumes `gen-harness.lib.mkCi`.
   - Sets `gen.ci.rootSurface.entry = "not-owed";`.
