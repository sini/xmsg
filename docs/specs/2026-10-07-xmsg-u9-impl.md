## 1. Problem & Context

Prior to Unit U9, Antigravity (`agy`) session registration proved caller identity ("caller belongs to conversation X") by reading `/proc/locks` to find the PID holding an exclusive `FLOCK` on `<presence_dir>/<conversation_id>.lock`.

### The Cross-Platform Problem
- Linux exposes the kernel file-lock table at `/proc/locks`, mapping `(major:minor:inode)` to the holding PID.
- macOS does **not** provide a mechanism to attribute a `flock` to a PID (Darwin kernel does not expose an flock table to userspace).
- Consequently, PR #1 added macOS process inspection via `proc_pidinfo` and `sysctl`, but explicitly barred `agy` on macOS with "agy is Linux only".

### The Identity Attribution Weakness
Even on Linux, relying solely on `/proc/locks` and argv matching introduces subtle risks:
1. `argv` is controlled by userspace (`prctl(PR_SET_MM_ARGV)` or process execution arguments) and can be spoofed by any process claiming to be `agy`.
2. Pi process verification relied on an `argv looks like pi` heuristic, allowing any node script with `"pi"` in its arguments to register as a Pi session (recorded as Gate Finding C3 in previous reviews).

## 2. Binding Architecture & Mechanisms

### 2.1 Antigravity Identity Proof (Linux & macOS)

When an agent process connects to `xmsg` over `register.sock` with `AgyRegisterRequest`:
1. **Peer UID Attestation:**
   `peer_uid == my_uid` (enforced via `SO_PEERCRED` / `LOCAL_PEERCRED`). Cross-user registration is rejected (`403 not_recipient`).
2. **Configuration Requirement:**
   At least one trusted `agy` executable path must be configured (`--agy-exe` CLI flag, repeatable, or `XMSG_AGY_EXE` environment variable).
   If no trusted executable is configured: **REFUSE registration** with `400 bad_request` ("no trusted agy executable configured"). There is **NO argv fallback** for Antigravity.
3. **Presence Lock Canonical Inode Resolution:**
   The server resolves the presence lock file at `<presence_dir>/<conversation_id>.lock`.
   Using `fs::metadata` (which follows symlinks to the canonical file), the server records `(target_dev, target_ino)`.
   If the file is missing or unreadable, registration returns `410 gone`.
4. **Ancestor Walk with Dual Attestation:**
   The server walks the registering peer's ancestor chain from `peer_pid` up to PID 1 (bounded at 32 steps):
   For each ancestor, the server checks **BOTH**:
   - **(a) EXECUTABLE:** The kernel-reported executable path (`readlink /proc/<pid>/exe` on Linux, `proc_pidpath` on macOS, `<proc_root>/<pid>/exe` in fixtures), never `argv`, matches a configured trusted `agy` executable. Canonicalized paths (`fs::canonicalize`) are compared so symlinks (e.g. Nix store wrappers) resolve to the true binary.
   - **(b) OPEN FILE:** The ancestor process currently holds the canonical presence lock open. The server queries the open file descriptors of the ancestor (`open_file_ids`) and verifies that `(target_dev, target_ino)` is present in the ancestor's open file list.
5. **Session Derivation & Key:**
   The first ancestor passing **both** (a) and (b) is accepted as the authentic session process.
   The server derives the immutable session key:
   $$\text{session\_key} = \text{"agy:"} \parallel \text{chosen\_pid} \parallel \text{":"} \parallel \text{starttime}$$
   `conversation_id` comes from the request payload, but it is only accepted because the ancestor has verified ownership of `<conversation_id>.lock` via (b).
6. **Linux Additional FLOCK Check:**
   On Linux (where `/proc/locks` exists):
   If an `FLOCK` holder line exists in `/proc/locks` for `(target_dev, target_ino)`:
   - It MUST equal `chosen_pid`. If it points to a different PID, or if multiple ambiguous holders exist, registration is **REFUSED**.
   - macOS skips this check because macOS cannot query lock holders.
7. **Liveness via PID + Starttime:**
   After registration, liveness of the session is determined strictly by `chosen_pid` + `process::starttime(proc_root, chosen_pid)`.
   There are no per-message lock checks. If the process terminates and PID is reused, `starttime` mismatch detects death immediately.

### 2.2 Pi Executable Verification (Gate Finding C3)

In `src/pi.rs`:
- Server supports configured trusted Pi entrypoints (`--pi-entrypoint`, repeatable, or `XMSG_PI_ENTRYPOINT`).
- When `--pi-entrypoint` is configured:
  1. The kernel executable must be `node` (or `nodejs`), verified via `process::exe_path`.
  2. The script argument (the first non-flag argument after node) must canonicalize to a configured trusted Pi entrypoint.
  3. The weak `argv looks like pi` heuristic is **completely replaced**.
- When `--pi-entrypoint` is NOT configured:
  - Fall back to the legacy `is_pi_cmdline` heuristic, explicitly documented in `README.md` as weaker.

## 3. Kernel Process Primitives (`src/process.rs`)

Behind the `proc_root` abstraction:
1. `pub fn exe_path(proc_root: &Path, pid: u32) -> io::Result<PathBuf>`
   - **Linux live:** `fs::read_link(Path::new("/proc").join(pid.to_string()).join("exe"))`.
   - **macOS live:** `libc::proc_pidpath(pid as libc::c_int, buf, buf_len)`.
   - **Synthetic fixture:** `fs::read_link(proc_root.join(pid.to_string()).join("exe"))` (or file path if regular file).
2. `pub fn open_file_ids(proc_root: &Path, pid: u32) -> io::Result<Vec<(u64, u64)>>`
   - **Linux live & fixture:** Read entries in `<proc_root>/<pid>/fd/`. For each file descriptor, query `fs::metadata` (following symlink) and extract `(meta.dev(), meta.ino())`.
   - **macOS live:**
     - Query open FDs via `libc::proc_pidinfo(pid, libc::PROC_PIDLISTFDS, 0, ...)`.
     - For each FD where `proc_fdtype == libc::PROX_FDTYPE_VNODE`:
     - Query vnode info via `libc::proc_pidfdinfo(pid, fd, PROC_PIDFDVNODEPATHINFO, ...)`.
     - Extract `(vnode.pvip.vip_vi.vi_stat.vst_dev as u64, vnode.pvip.vip_vi.vi_stat.vst_ino)`.
   - Scans **only ancestors**, never all system processes.

## 5. Acceptance Oracles & Test Matrix

### 5.1 Gating Oracle Suite (`tests/gate_u9_identity.rs`)
1. **Accept:** Ancestor process is a trusted executable AND has the presence lock file open.
2. **Refuse - Untrusted Exe:** Ancestor has the lock file open, but executable path is untrusted (even if `argv` claims to be `agy`).
3. **Refuse - Lock Not Open:** Ancestor is a trusted executable, but does not have the presence lock file descriptor open.
4. **Refuse - Non-Ancestor Holder:** A non-ancestor process holds the lock file open (ancestor walk does not reach it).
5. **Refuse - No Trusted Exe Configured:** Registration attempt when `--agy-exe` is empty fails with clear error.
6. **Refuse - Inode Mismatch (Symlink Attack):** Presence path is symlinked to a different file; open file inode differs from canonical presence file inode.
7. **Refuse - Linux FLOCK Mismatch:** Another PID holds the FLOCK in `/proc/locks`.
8. **Liveness Verification:** Process PID reused with different starttime is immediately detected as gone.
9. **Pi Verification - Trusted Entrypoint:** Node with configured trusted entrypoint passes.
10. **Pi Verification - Untrusted Entrypoint:** Node with untrusted script argument is rejected when trusted entrypoint is configured.
