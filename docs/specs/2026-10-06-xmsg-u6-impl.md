## 1. Findings & Threat Models

### 1.1 B1: Reserved Prefix Bypass over HTTP

- **Vulnerability:** `src/http.rs` checked `req.from.trim().starts_with("session:")` prior to calling `inbox::sanitize_from`. Leading invisible characters (e.g. U+200B zero-width space, ASCII BEL `\x07`, or quotes/brackets `"<`) bypassed the prefix check and were subsequently stripped by the sanitizer, yielding the reserved badge `xmsg@<host> · session:evil`.
- **Threat Model:** Any process capable of reaching the local HTTP endpoint could forge the visual identity badge reserved for verified local sessions.

### 1.2 B2: Caller-Asserted Pi Identity & Cross-Harness Impersonation

- **Vulnerability:**
  - `src/pi.rs` accepted `sessionId` directly from `PiRegisterRequest` body without deriving or verifying it against the OS process.
  - `verify_pi_process` merely checked `cmdline.contains("pi")`, allowing unrelated programs (e.g. `python3 -c "spin()"`) to register.
  - The reply authorization check in `src/agent.rs` compared raw `session_id` strings without binding the session to its originating harness (`claude`, `agy`, or `pi`).
- **Threat Model:** A rogue process could claim the `sessionId` of any Claude session, hijack its message queue, and reply to messages intended for that Claude session.

### 1.3 B3: Unsanitized Attested Sender Name & Envelope Breakout

- **Vulnerability:**
  - `agent.rs` constructed the sender name on `send` as `format!("xmsg@{} · session:{}", host_label, caller_name)` without sanitization, without stripping `"`, `<`, `>`, newlines, or control characters, and without applying the 64-character length cap.
  - `inbox::assemble_envelope` directly interpolated `from_name` into `<cross-session-message from-name="{from_name}">`.
  - Hostile characters in session names (e.g. injected closing tags `</cross-session-message>`) resulted in XML envelope breakout and arbitrary content injection into victim inboxes.
  - Unsanitized sender names were also relayed into `agy --title` and inbox headers.

### 1.4 Majors & Policy Gaps

- **M1:** `agent.sock` and `register.sock` performed unbounded line reads, and `agent.sock` `send` lacked a `max_body` bound.
- **M2:** `storage::ack_pi_message` updated messages by ID alone without checking `session_id`, allowing any connected Pi session to ack another session's pending messages.
- **M3:** The `messages` table was never purged by TTL, and the Pi pending queue lacked a per-session capacity limit.
- **M4:** `agy.rs` relayed raw child stdout/stderr in HTTP error responses (`CredentialsStale`, `InboxUnavailable`).
- **P1:** `README.md` was obsolete, omitting `agent.sock`, `register.sock`, MCP, Pi, no-auth HTTP posture, same-UID trust model, and accurate sanitization documentation.

## 2. Architecture & Mechanisms

### 2.1 B1: Post-Sanitization Prefix Enforcement & Structural Separation

1. **Sanitize First:**
   - In `src/inbox.rs`, `sanitize_from` performs character stripping, category filtering, whitespace normalization, and trimming *first*.
   - Immediately following normalization, `sanitize_from` inspects the cleaned text: if `cleaned.to_lowercase().starts_with("session:")` or `starts_with("session/")`, it returns `Err(AppError::BadSender("reserved prefix 'session:' is not allowed in unauthenticated sender name"))`.
   - Unicode normalization (NFKC) and case-folding ensure no homoglyph or zero-width prefix bypass is possible.
2. **Structural Badge Generation:**
   - The attested badge `xmsg@<host> · session:<name>` is constructed strictly via a distinct internal function `sanitize_attested_from(host_label, caller_name)`.
   - The unauthenticated HTTP path calls `sanitize_from` which strictly forbids `session:` / `session/`.

### 2.2 B2: Attested Pi Identity & Harness-Tagged Authorization

1. **Server-Derived Pi Identity:**
   - The server completely ignores any caller-provided `sessionId` in `PiRegisterRequest`.
   - The server derives the Pi session ID from the attested OS process:
     $$\\text{derived_id} = \\text{"pi:"} \\parallel \\text{peer_pid} \\parallel \\text{":"} \\parallel \\text{starttime}$$
   - The request body is permitted to supply only an optional display `sessionName`.
2. **Robust Executable & Script Basename Check:**
   - In `verify_pi_process`, the server splits `/proc/<pid>/cmdline` by `\0`.
   - It parses `argv[0]`. If `argv[0]` is `pi` or ends with `/pi`, it matches.
   - If `argv[0]` is a JS/TS runtime (`node`, `bun`, `deno`), it inspects `argv[1]` and verifies its basename is `pi`, `pi.js`, or `pi.mjs`.
   - Substring matches on arbitrary arguments (such as `python3 -c "spin()"`) are explicitly rejected.
3. **Harness-Bound Identity & Reply Authorization:**
   - In `src/storage.rs`, the `messages` table records `recipient_harness TEXT NOT NULL DEFAULT 'claude'`.
   - When storing a delivered message, `recipient_harness` is recorded as `target_session.harness` (`"claude"`, `"agy"`, or `"pi"`).
   - In `src/agent.rs`, reply authorization validates:
     $$\\text{caller.harness} == \\text{msg.recipient_harness} \\quad \\land \\quad \\text{caller.session_id} == \\text{msg.session_id}$$
   - A Pi or Antigravity session can never alias or reply to a message intended for a Claude session.
4. **Registration Lifecycle & Disconnect Cleanup:**
   - If a registration's derived ID is already active in `PiStore` under a differing PID, the registration is rejected.
   - On disconnect, the session is removed from `PiStore` only if the active entry's PID and starttime match the disconnecting peer.

### 2.3 B3: Attested Sender Sanitization & Envelope Attribute Escaping

1. **Attested Sender Sanitizer (`sanitize_attested_from`):**
   - Applies the identical category stripping as HTTP: removes `"`, `<`, `>`, `\n`, `\r`, and Unicode categories Cc, Cf, Cs, Zl, Zp.
   - Collapses whitespace and trims.
   - Formats `xmsg@{host_label} · session:{cleaned_caller_name}`.
   - Truncates the total string to 64 Unicode scalar characters.
2. **Defense-in-Depth Attribute Escaping:**
   - In `inbox::assemble_envelope`, `from_name` replaces any `"` with `&quot;` (or strips `"`), ensuring XML attribute breakout is impossible even if an unsanitized string were supplied.
3. **Sink Hardening:**
   - In `agy.rs`, the `--title` argument and `[xmsg] from:` headers consume the sanitized, capped `from_name`.

### 2.4 Majors M1–M4 Implementation

1. **M1 (Bounded Frames & Payload Size):**
   - In `agent.rs`, `pi.rs`, and `agy.rs`, `read_line` operates on `tokio::io::AsyncReadExt::take(reader, max_body + 4096)`. If a frame exceeds the limit or lacks a terminating newline within the bound, the server returns `bad_request` and terminates the stream.
   - In `agent.rs` `send` handler, `text.len() <= max_body` is enforced.
2. **M2 (Session-Scoped Pi Ack):**
   - `storage::ack_pi_message(conn, session_id, message_id)` executes:
     `UPDATE pi_pending_messages SET delivered_at = ?1 WHERE id = ?2 AND session_id = ?3 AND delivered_at IS NULL`.
3. **M3 (TTL Purge & Pi Queue Cap):**
   - `storage::purge_messages(conn, ttl_secs)` deletes records from `messages` where `created_at < now - ttl`.
   - `insert_pi_message` checks current pending messages for `session_id`. If pending count $\\ge 100$, it returns `AppError::InboxUnavailable("pi session message queue is full")` (HTTP 503).
4. **M4 (Agy Error Sanitization):**
   - `agy.rs` logs full child output locally via `tracing::warn!` (truncated to 200 characters).
   - The returned `AppError::CredentialsStale` and `AppError::InboxUnavailable` contain static error strings (`"authentication failed"`, `"delivery failed"`), leaking no stdout/stderr to HTTP clients.

### 2.5 Policy P1: Complete Documentation of Security & Trust Boundaries

- Rewrite `README.md` to document:
  - Both Unix sockets (`register.sock` and `agent.sock`) and their purpose.
  - MCP server subcommand (`xmsg mcp`), CLI registration (`xmsg register agy`), and the Pi extension.
  - Endpoints: messages, replies, long-polling, and session enumeration.
  - **No-Auth HTTP Posture:** Explicit warning that the HTTP server provides no authentication and must strictly bind to loopback (`127.0.0.1`).
  - **Same-UID Trust Boundary:** Sockets enforce mode `0700` and `SO_PEERCRED` UID. Any process running under the same UID resides within the trust boundary.
  - **Attestation & Sanitization Guarantees:** Ancestor walk attestation, derived Pi identities, 64-char cap, XML escaping, and body tag defusing.

### 2.6 Minors & Oracle Honesty

1. **JSON Construction:** In `agy.rs`, replace `format!(r#"{{"status":"error","detail":"{e}"}}"#)` with `serde_json::json!`.
2. **Peer PID Pinning:** In `agent.rs`, verify peer starttime at accept and ensure PID liveness and starttime continuity across calls.
3. **Safe Socket Unlinking:** In `agent.rs` and `agy.rs`, before removing a socket file on startup, attempt a `UnixStream::connect`. If successful, fail with `InsecureSocketDir("another instance is actively listening")`.
4. **SQLite Modes:** Set `0700` on database directory and `0600` on the SQLite database file in `main.rs`.
5. **Database Async Boundaries:** Wrap synchronous rusqlite queries in `tokio::task::spawn_blocking`.
6. **Long-Poll Concurrency Cap:** Bound concurrent long-poll requests using a `tokio::sync::Semaphore` (capacity 128) in `AppState`.
7. **Agy Argv Terminator:** Insert `"--"` before the conversation ID in `agy.rs`.
8. **Oracle Honesty:**
   - In `ci/tests/basic.nix`, replace `true == true` with a test evaluating `packages.x86_64-linux.default.meta.description`.
   - In `tests/pi_proc.rs`, test that `python3 -c "spin()"` is rejected.
   - Add permanent test cells for B1 (`tests/gate_probe_http.rs`), B2/B3 (`tests/gate_probe_pi.rs`), cross-harness collision, and `/proc/<pid>/stat` comm handling.
   - Refactor `default_socket_dir` to accept an optional environment variable slice (`socket_dir_for_env`) eliminating `std::env::set_var` race conditions in tests.

## 3. Gating Oracles & Red Demonstrations

### 3.1 Measured Red Demonstrations at `720a1d6`

- **Red Demo B1 (HTTP Prefix Bypass):**
  - Run at `720a1d6`: `"\u{200b}session:evil"` returned `202 Accepted` with `fromName="xmsg@test-host · session:evil"`.
  - Fix target: Returns `400 Bad Request` (`outcome=bad_sender detail="reserved prefix"`).
- **Red Demo B2 (Pi Registration Impersonation):**
  - Run at `720a1d6`: Registered victim's session ID `victim-claude`, followed by successful forged reply over `agent.sock`.
  - Fix target: Server derives `pi:<pid>:<starttime>`; reply from mismatched harness/session fails with `not_recipient`.
- **Red Demo B3 (Attested Name Envelope Breakout):**
  - Run at `720a1d6`: `send` with hostile session name resulted in `closes == 2` in the raw delivered inbox line and 103 characters in `fromName`.
  - Fix target: Sanitized to $\\le 64$ chars, quotes stripped/escaped, `closes == 1`.
- **Red Demo O2 (Pi Process Verification):**
  - Run at `720a1d6`: `python3 -c "spin()"` was accepted because `cmdline.contains("pi")` matched `spin`.
  - Fix target: `verify_pi_process` returns `BadRequest("peer process is not a pi instance")`.
