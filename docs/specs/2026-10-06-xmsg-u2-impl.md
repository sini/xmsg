## 1. Problem & Context

In v1 (U1), outside callers can deliver messages into live agent sessions, but the receiving agent has no addressable, authorized mechanism to reply:
- Calling an outside HTTP endpoint directly via shell `curl` is denied by the auto-mode classifier or prompts the user.
- Sending a reply via native harness messaging fails because the sender is outside the agent harness.

U2 introduces an authorized, owner-ruleable reply path and orchestrator tools:
1. **Persistent SQLite Store**: The server maintains delivery records and replies in `$XDG_STATE_HOME/xmsg/xmsg.db`, with TTL purging. Message bodies are never stored; reply bodies are stored.
2. **Reply Endpoints & Long-Polling**:
   - `POST /v1/sessions/{ref}/messages` returns a unique `message_id` (ULID) and appends an envelope footer:
     `\n\n[xmsg] message_id={message_id} — reply with the xmsg reply tool`.
   - `GET /v1/messages/{id}` returns message metadata and replies.
   - `GET /v1/messages/{id}/replies?after=<seq>&wait=<s>` provides long-polling (capped at 60 s) via async notification (`tokio::sync::broadcast`).
   - `POST /v1/messages/{id}/replies` records a reply, strictly enforcing that only the recipient session can reply (403 `not_recipient`).
3. **`xmsg mcp` Stdio Subcommand**:
   - Exposes three tools: `list()`, `send(ref, text)`, `reply(message_id, text)`.
   - None is marked `requiresUserInteraction`.
   - Discovers the calling session by walking `/proc/<pid>/stat` parent PIDs upwards through possible wrapper layers (Nix wrappers) to the first ancestor holding a session file.
   - `send` strictly derives `from` from the caller's session name; any caller-supplied `from` argument is rejected.

## 2. Unit U2 Scope & Boundaries

### In Scope for U2
- **Storage Layer (`storage.rs`)**:
  - SQLite database using `rusqlite` with `bundled` feature.
  - Schema:
    ```sql
    CREATE TABLE IF NOT EXISTS messages (
        id TEXT PRIMARY KEY,
        created_at INTEGER NOT NULL,
        session_id TEXT NOT NULL,
        from_name TEXT NOT NULL,
        bytes INTEGER NOT NULL,
        outcome TEXT NOT NULL
    );
    CREATE TABLE IF NOT EXISTS replies (
        seq INTEGER PRIMARY KEY AUTOINCREMENT,
        message_id TEXT NOT NULL REFERENCES messages(id),
        created_at INTEGER NOT NULL,
        replier_session_id TEXT NOT NULL,
        text TEXT NOT NULL
    );
    CREATE INDEX IF NOT EXISTS idx_replies_message_seq ON replies(message_id, seq);
    CREATE INDEX IF NOT EXISTS idx_replies_created_at ON replies(created_at);
    ```
  - Config flags on `serve`:
    - `--db-path` (env `XMSG_DB_PATH`, default `~/.local/state/xmsg/xmsg.db` or `:memory:` in tests).
    - `--reply-ttl` (env `XMSG_REPLY_TTL`, default `604800` seconds / 7 days).
  - Purge logic: removes replies where `created_at < now - reply_ttl`.
- **HTTP Server Additions (`http.rs`, `error.rs`)**:
  - `POST /v1/sessions/{ref}/messages`:
    - Generates ULID `message_id`.
    - Appends envelope footer: `\n\n[xmsg] message_id={message_id} — reply with the xmsg reply tool`.
    - Inserts message record into SQLite.
    - Returns HTTP 202 `DeliveryResponse` including `message_id` (supporting both `messageId` and `message_id`).
  - `GET /v1/messages/{id}`:
    - Returns delivery record and all replies so far (`MessageDetailResponse`, HTTP 200) or HTTP 404 `not_found`.
  - `GET /v1/messages/{id}/replies?after=<seq>&wait=<s>`:
    - Verifies message exists; returns 404 `not_found` if not found.
    - Long-polls with timeout capped at 60 s.
    - Subscribes to notification broadcast *before* querying SQLite to eliminate notification races.
    - Returns array of replies with `seq > after`.
    - If timeout expires with no replies, returns empty array `[]` (HTTP 200).
  - `POST /v1/messages/{id}/replies`:
    - Body: `SendReplyRequest { session_ref, text }` with `#[serde(rename_all = "camelCase")]`.
    - Resolves `session_ref` to a live session in `sessions_dir`.
    - Checks recipient session ID against `messages.session_id`. If mismatched: HTTP 403 `not_recipient`.
    - On success: inserts reply into SQLite, notifies long-poll waiters, returns HTTP 201 `ReplyRecord`.
- **MCP Server (`mcp.rs`)**:
  - Subcommand `xmsg mcp` running standard newline-delimited JSON-RPC 2.0 over stdio.
  - Flags:
    - `--sessions-dir` (env `XMSG_SESSIONS_DIR`, default `~/.claude/sessions`).
    - `--xmsg-url` (env `XMSG_URL`, default `http://127.0.0.1:7787`).
  - Ancestor process walk: parameterized as `find_ancestor_session_in(proc_root, sessions_dir, start_pid)` to allow complete unit testability in the Nix sandbox. Walks parent PIDs upwards through possible Nix wrappers (`.headroom-wrapp`, `.serena-wrapped`) to the first ancestor holding a live session file, bounded at PID 1.
  - Lazy resolution on tool execution: returns clean MCP tool error if run outside an agent session.
  - Tools:
    - `list()`: calls `GET /v1/sessions`.
    - `send(ref, text)`: rejects `from` argument; derives `from` from caller session name and POSTs to `/v1/sessions/{ref}/messages`.
    - `reply(message_id, text)`: POSTs to `/v1/messages/{id}/replies` using caller's session ID.
    - None marked `requiresUserInteraction`.
- **Gating Oracle (§8.5, §8.3a)**:
  - Integration tests in `tests/e2e_replies.rs`, `tests/e2e_mcp.rs`, and `tests/ancestor_walk.rs`.
  - Verified by `cargo test`, `cargo clippy`, `nix build .#default`, and `nix flake check ./ci`.

### Out of Scope for U2
- v3 Antigravity / pi adapters (`register.sock`, `agentapi`).
- nix-config aspect changes (permissions allow list, user mcpServers configuration).

### 3.3 Core Logic

#### 1. Message Delivery with Envelope Footer & SQLite Insert
When `POST /v1/sessions/{ref}/messages` is called:
1. Generate ULID: `let message_id = ulid::Ulid::new().to_string();`.
2. Format raw body: format with footer:
   ```rust
   let body_with_footer = format!("{raw_text}\n\n[xmsg] message_id={message_id} — reply with the xmsg reply tool");
   ```
3. Encode transport line: `inbox::encode_transport_line(&from_name, &body_with_footer)?`.
4. Deliver to session socket.
5. Record message in SQLite:
   ```sql
   INSERT INTO messages (id, created_at, session_id, from_name, bytes, outcome)
   VALUES (?1, ?2, ?3, ?4, ?5, 'delivered');
   ```
6. Return HTTP 202 `DeliveryResponse { session_id, from_name, bytes, message_id }`.

#### 2. Long-Polling Replies without Race Conditions
`GET /v1/messages/{id}/replies?after=<seq>&wait=<s>`:
1. Check message exists in `messages` table. If not: return HTTP 404 `not_found`.
2. Parse `after` (default 0) and `wait` (clamped: `wait.min(60)`).
3. If `wait > 0`:
   - **Subscribe to notification broadcast BEFORE reading the database:**
     `let mut rx = state.notify_tx.subscribe();`
4. Query SQLite for replies with `message_id == id AND seq > after ORDER BY seq ASC`.
5. If non-empty or `wait == 0`: return `Json(replies)`.
6. If empty and `wait > 0`:
   - Wait on `tokio::time::timeout(Duration::from_secs(wait), async { loop { match rx.recv().await { Ok(msg_id) if msg_id == id => break, Err(RecvError::Lagged(_)) => break, _ => {} } } })`.
   - Query SQLite again for `message_id == id AND seq > after ORDER BY seq ASC`.
   - Return `Json(replies)` (empty array `[]` on timeout).

#### 3. Recipient Authorization on Replies
`POST /v1/messages/{id}/replies`:
1. Parse JSON body `SendReplyRequest { session_ref, text }`. Reject unknown fields. Reject empty text.
2. Resolve `session_ref` against `sessions_dir`. If session is not live or does not exist: return appropriate 404/410.
3. Query SQLite for message by `id`. If not found: return HTTP 404 `not_found`.
4. Verify recipient:
   If `resolved_session.session_id != message.session_id`:
   return HTTP 403 `not_recipient` with detail: `"session {session_ref} is not the recipient of message {id}"`.
5. Insert reply row:
   ```sql
   INSERT INTO replies (message_id, created_at, replier_session_id, text)
   VALUES (?1, ?2, ?3, ?4);
   ```
6. Purge old replies:
   ```sql
   DELETE FROM replies WHERE created_at < ?1;
   ```
7. Broadcast notification: `state.notify_tx.send(id.clone());`.
8. Return HTTP 201 with `ReplyRecord`.

#### 4. Parameterized Ancestor Process Walk (`mcp.rs`)
Function:
```rust
pub fn find_ancestor_session_in(
    proc_root: &Path,
    sessions_dir: &Path,
    start_pid: u32,
) -> Result<Session, AppError>
```
1. Set `curr_pid = start_pid`.
2. Loop (up to 32 iterations):
   - Read `proc_root.join(curr_pid.to_string()).join("stat")`.
   - Split after the last `')'`, extract field 4 (`ppid`).
   - If `ppid <= 1`: break.
   - Check if `sessions_dir.join(format!("{ppid}.json"))` exists.
   - If it exists: read entry, check `is_pid_live_in(proc_root, ppid, &entry.proc_start)`. If live: return this session!
   - `curr_pid = ppid`.
3. If no live ancestor session found, return `AppError::NotFound("no ancestor session found".into())`.
Convenience wrapper:
```rust
pub fn find_ancestor_session(sessions_dir: &Path) -> Result<Session, AppError> {
    find_ancestor_session_in(Path::new("/proc"), sessions_dir, std::process::id())
}
```

#### 5. Stdio MCP Server (`mcp.rs`)
Protocol: Newline-delimited JSON-RPC 2.0 over stdin/stdout.
- `initialize`: returns `protocolVersion: "2024-11-05"`, `capabilities: { tools: { listChanged: false } }`, `serverInfo: { name: "xmsg", version: "0.1.0" }`.
- `notifications/initialized`: no response.
- `ping`: returns `{}`.
- `tools/list`: returns 3 tool definitions:
  - `list`: description "List active agent sessions", schema `{ "type": "object", "properties": {}, "additionalProperties": false }`.
  - `send`: description "Deliver message to session", schema `{ "type": "object", "properties": { "ref": { "type": "string" }, "text": { "type": "string" } }, "required": ["ref", "text"], "additionalProperties": false }`.
  - `reply`: description "Reply to received message", schema `{ "type": "object", "properties": { "message_id": { "type": "string" }, "text": { "type": "string" } }, "required": ["message_id", "text"], "additionalProperties": false }`.
  None has `requiresUserInteraction`.
- `tools/call`:
  - `list`: calls `GET /v1/sessions`. Returns JSON content.
  - `send`: checks for illegal `from` argument; returns tool error if present. Calls `find_ancestor_session`. Derives `from = caller.name.unwrap_or(caller.session_id)`. Calls `POST /v1/sessions/{ref}/messages`. Returns result.
  - `reply`: calls `find_ancestor_session`. Calls `POST /v1/messages/{message_id}/replies` with `sessionRef = caller.session_id`. Returns result.
  - Tool results formatted as `{ "content": [{ "type": "text", "text": "..." }], "isError": bool }`.

## 4. Acceptance Oracles (§8.5, §8.3a)

The U2 suite adds tests run by `cargo test` and enforced via `doCheck = true`:

1. **Reply Round-Trip (`tests/e2e_replies.rs`)**:
   - `POST` a message to live session inbox -> returns `202 Accepted` with `messageId`.
   - Asserts the raw line received by the stand-in socket contains `[xmsg] message_id={messageId} — reply with the xmsg reply tool`.
   - `POST` a reply to `/v1/messages/{messageId}/replies` as recipient -> returns 201.
   - `GET /v1/messages/{messageId}/replies` returns the reply.
   - `GET /v1/messages/{messageId}` returns `MessageDetailResponse` with delivery metadata and replies list.

2. **Recipient Authorization Check (403 `not_recipient`)**:
   - Attempt to reply to `messageId` with a different live session ref -> asserts HTTP 403 `not_recipient`.

3. **Reply Error Conditions**:
   - Reply to non-existent `message_id` -> asserts 404 `not_found`.
   - Reply with unknown `sessionRef` -> asserts 404 `not_found`.
   - Reply with empty `text` or extra JSON fields -> asserts 400 `bad_request`.

4. **Long-Polling Notification, Timeout & Clamping**:
   - Task A calls `GET /v1/messages/{id}/replies?after=0&wait=10`.
   - Task B POSTs a reply after 100 ms -> Task A returns immediately with the new reply.
   - Call with `wait=1` and no incoming replies -> returns `[]` after ~1 s.
   - Call with `wait=0` -> returns immediately without waiting.
   - Call with non-existent message ID -> returns 404 `not_found` immediately.

5. **TTL Purge**:
   - Insert reply with timestamp older than TTL.
   - POST a new reply -> asserts old reply is purged from SQLite.

6. **Ancestor Walk Fixture (`tests/ancestor_walk.rs`)**:
   - Builds mock `/proc` tree: Session PID 100 -> Wrapper PID 101 -> MCP PID 102.
   - Tests:
     - `find_ancestor_session_in` starting at PID 102 traverses wrapper PID 101 and returns session for PID 100.
     - Starting at PID with parent 1 returns `NotFound`.
     - Invalid `procStart` on ancestor returns `NotFound`.

7. **MCP Stdio Protocol Round-Trips (`tests/e2e_mcp.rs`)**:
   - Interacts with `xmsg mcp` stdio handler via JSON-RPC 2.0.
   - Asserts `initialize` and `tools/list` return 3 tools, none marked `requiresUserInteraction`.
   - Asserts calling `send` tool with explicit `from` argument returns an error (forbidden override).
   - Asserts calling `send` with valid ancestor session delivers to stand-in inbox with derived `from`.
   - Asserts calling `reply` delivers reply to `/v1/messages/{id}/replies`.

## 6. Architecture & Spec Deviations

### 6.1 Hand-rolled JSON-RPC 2.0 stdio Server vs `rmcp` Crate (§8.3)
- **Deviation**: The v1 design referenced using `rmcp` for stdio MCP tool serving. `xmsg` implements a lightweight, hand-rolled newline-delimited JSON-RPC 2.0 protocol loop in `src/mcp.rs` rather than pulling in external MCP framework crates.
- **Rationale**: Keeps `xmsg` dependency-light, builds quickly, and matches the pattern proven in `gen-lsp`.
- **Protocol Negotiation**: In response to `initialize`, `xmsg` inspects the client's requested `params.protocolVersion`. If the version is in `SUPPORTED_PROTOCOL_VERSIONS` (`["2025-06-18", "2024-11-05"]`), `xmsg` echoes that version; otherwise it defaults to `"2025-06-18"`.

### 6.2 Synchronous `xmsg mcp` Execution Path (No Outer Tokio Runtime)
- **Architecture**: `main()` in `src/main.rs` is a standard synchronous function (`fn main() -> Result<(), ...>`), NOT `#[tokio::main]`.
- **Mechanism**: The multi-threaded Tokio runtime is constructed solely within `Commands::Serve`. When `Commands::Mcp` is invoked, `run_mcp_loop` executes in a pure synchronous thread context.
- **Rationale**: Eliminates Tokio panic `Cannot drop a runtime in a context where blocking is not allowed` which occurs if `reqwest::blocking` is used inside an active async Tokio thread context.
- **Verification Oracle**: `tests/e2e_mcp.rs::test_shipped_binary_mcp_initialize_and_tool_call` executes the compiled binary `env!("CARGO_BIN_EXE_xmsg")` directly, issuing `initialize` and `tools/call list` over piped stdio, asserting successful JSON-RPC results and exit code 0.
