## 1. Scope Boundaries

### In Scope
1. **Adapter Abstraction (`src/adapter.rs` or `src/registry.rs`):**
   - Formalize `HarnessAdapter` interface (`list`, `liveness`, `deliver`).
   - Refactor `claude` harness onto this adapter interface with zero behavior change.
   - All U1 and U2 test suites remain green unmodified.
2. **Antigravity (`agy`) Adapter (`src/agy.rs`):**
   - **Discovery:** Read presence locks from `~/.gemini/antigravity-cli/presence/<conversation_id>.lock` (configurable via `XMSG_AGY_PRESENCE_DIR` / CLI arg).
   - **Holder PID Resolution:** Parse `/proc/locks` read-only by matching filesystem `(dev, inode)` against lock entries. **Never test-acquire or flock-test.**
   - **Liveness:** Live while presence lock is held by active PID in `/proc/locks`. Gone when lock is dropped. Stale when registration credentials have been invalidated.
   - **Listing:** Unregistered live session lists with `registered: false`, registered live session with `registered: true`. Every session has `harness: "agy"`.
   - **Delivery:** Execute `agy agentapi send-message --title <from-name> <conversation_id> <body>` as an argv vector with no shell. Pass `ANTIGRAVITY_LS_ADDRESS` and `ANTIGRAVITY_CSRF_TOKEN` in the **child environment only**; never in argv.
   - **Delivery Status Codes:**
     - Exit 0 -> HTTP 202 `Accepted` with `DeliveryResponse`.
     - Output contains "Unauthenticated" or connection refused -> marks registration stale and returns HTTP 503 `credentials_stale`.
     - Other non-zero exit -> HTTP 502 `inbox_unavailable`.
     - Timeout (5s) -> HTTP 504 `inbox_timeout`.
   - **Envelope:** Plain header line `[xmsg] from=<from-name> message_id=<message_id> — reply with the xmsg reply tool\n\n<body_text>` (§9.4).
3. **Registration Server (`register.sock`):**
   - Listen on `$XDG_RUNTIME_DIR/xmsg/register.sock` (mode 0700 dir, configurable in tests).
   - Verify peer on Unix stream connect:
     1. `SO_PEERCRED` matches server process UID (`peer_uid == my_uid`).
     2. Lock check: `presence/<conversation_id>.lock` is held by a PID in `/proc/locks`.
     3. Ancestor walk: Peer PID's parent chain in `/proc/<pid>/stat` (bounded at PID 1) reaches the lock holder PID.
   - Store credentials in **memory only**: atomic upsert per `conversation_id`. Dropped when presence lock is released. Never written to SQLite, logs, or API payloads.
4. **Command `xmsg register agy`:**
   - Reads `ANTIGRAVITY_LS_ADDRESS`, `ANTIGRAVITY_CSRF_TOKEN`, and `ANTIGRAVITY_CONVERSATION_ID` from env.
   - Connects to `register.sock` and transmits JSON payload.
   - **Invariant:** Always prints `{"injectSteps":[]}` to stdout and exits with code 0, even if server is down or socket unreachable. Failures log to stderr only.
5. **First-Contact Definition File:**
   - Ship `docs/agy/xmsg-register.md` documenting the hook / command definition.
6. **MCP `reply` tool for `agy`:**
   - Ancestor walk from MCP process PID identifies lock holder PID in `/proc/locks`, mapping to `conversation_id`.
   - Derives caller `sessionRef = conversation_id` without requiring credentials.

### Out of Scope
- `pi` harness (deferred to Unit U4).
- Modifications to `nix-config` or host configurations.
- Real Antigravity session interactions during automated tests (tests use isolated mocks and fixtures).

## 3. Core Mechanisms

### 3.1 Read-Only Lock Inspection via `/proc/locks`
Function:
```rust
pub fn find_lock_holder(
    proc_locks_path: &Path,
    dev_major: u32,
    dev_minor: u32,
    inode: u64,
) -> io::Result<Option<u32>>
```
1. Reads `proc_locks_path` line by line.
2. Parses fields:
   - field 1: type (`FLOCK` or `POSIX`)
   - field 3: access (`WRITE` or `READ`)
   - field 4: pid
   - field 5: device and inode formatted as `maj:min:ino` (e.g. `00:2e:1148992`).
3. Compares device major/minor (parsed as hex) and inode (parsed as decimal).
4. Matches exclusive `WRITE` locks for the specified target inode.
5. Returns `Some(pid)` if found, or `None`.
6. **Invariant:** Does NOT open or flock the target file.

### 3.2 Registration Verification & In-Memory Store
On connection to `register.sock`:
1. Extract peer credentials using `tokio::net::UnixStream::peer_cred()`.
2. Verify `peer_cred.uid == current_process_uid`. If not, return error and abort.
3. Read JSON `AgyRegisterRequest` from stream.
4. Check `presence_dir.join(format!("{conversation_id}.lock"))`:
   - Must exist. Extract `(dev, inode)`.
   - Call `find_lock_holder(proc_locks_path, dev_major, dev_minor, inode)` to get `holder_pid`.
   - Lock must be held; if `holder_pid` is None, reject registration.
5. Walk ancestor tree from `peer_cred.pid`:
   - Trace parent PIDs in `/proc/<pid>/stat` upwards to PID 1.
   - If `holder_pid` is in the ancestor chain, accept!
   - If walk reaches PID 1 without finding `holder_pid`, reject registration.
6. Insert into `AgyStore`:
   ```rust
   store.write().unwrap().insert(conversation_id, AgyCredentials {
       ls_address: req.ls_address,
       csrf_token: req.csrf_token,
       is_stale: false,
   });
   ```
7. Return `{"status":"ok"}\n` over socket.

### 3.3 Delivery Execution
When `POST /v1/sessions/{ref}/messages` targets an `agy` session:
1. Envelope formatting (§9.4):
   ```rust
   let envelope = format!(
       "[xmsg] from={} message_id={} — reply with the xmsg reply tool\n\n{}",
       from_name, message_id, body_text
   );
   ```
2. Look up credentials in `AgyStore`:
   - If missing: return HTTP 503 `credentials_stale` (or 404 if session not found).
   - If `is_stale == true`: return HTTP 503 `credentials_stale`.
3. Check presence lock is still held in `/proc/locks`:
   - If lock is gone: remove from `AgyStore` and return HTTP 410 `Gone`.
4. Spawn command:
   ```rust
   let mut cmd = tokio::process::Command::new("agy");
   cmd.arg("agentapi")
      .arg("send-message")
      .arg("--title")
      .arg(from_name)
      .arg(&session.session_id)
      .arg(&envelope)
      .env("ANTIGRAVITY_LS_ADDRESS", &creds.ls_address)
      .env("ANTIGRAVITY_CSRF_TOKEN", &creds.csrf_token);
   ```
   **Security Invariant:** Credentials exist strictly in child environment variables; never passed in argv vector or logged.
5. Await execution with 5-second timeout:
   - On timeout -> return HTTP 504 `inbox_timeout`.
   - On exit status 0 -> return HTTP 202 `Accepted` with `DeliveryResponse`.
   - On non-zero exit:
     - If output contains `"Unauthenticated"` or `"connection refused"`:
       mark `creds.is_stale = true` in store and return HTTP 503 `credentials_stale`.
     - Otherwise return HTTP 502 `inbox_unavailable`.

### 3.4 CLI Subcommand `xmsg register agy`
1. Read env:
   - `conv_id = env("ANTIGRAVITY_CONVERSATION_ID")`
   - `ls_addr = env("ANTIGRAVITY_LS_ADDRESS")`
   - `csrf_token = env("ANTIGRAVITY_CSRF_TOKEN")`
2. Connect to `register.sock`.
3. Write payload: `{"conversation_id": conv_id, "ls_address": ls_addr, "csrf_token": csrf_token}\n`.
4. Output rule:
   - **Always print `{"injectSteps":[]}\n` to stdout.**
   - **Always exit with status code 0.**
   - If any step fails (socket unreachable, server down, missing env vars), print notice to stderr only and exit 0.

### 3.5 MCP `reply` Tool Routing for `agy`
In `execute_tool("reply")`:
1. Walk ancestor PIDs starting from `std::process::id()`.
2. First check Claude session files (`sessions_dir/<ppid>.json`).
3. If not found, check `/proc/locks` for any presence lock held by an ancestor PID.
4. If ancestor PID holds `presence/<conv_id>.lock`:
   - Resolve calling session as `conversation_id`.
   - Post reply to `/v1/messages/{message_id}/replies` with `sessionRef: conversation_id`.

## 4. Acceptance Oracles & Gating Tests

1. **Proc Locks Read-Only Parser (`tests/agy_proc_locks.rs`)**:
   - Fixture `/proc/locks` and mock presence file:
     - Successfully resolves holder PID from lock line matching `(dev, inode)`.
     - Handles hex major/minor conversions.
     - Ignores other inodes and read locks.
     - Confirms lock is not acquired or modified by `xmsg`.
2. **Registration Server Verification (`tests/e2e_register.rs`)**:
   - Peer UID mismatch -> connection closed / rejected.
   - Non-descendant peer PID -> rejected.
   - Dead/missing presence lock -> rejected.
   - Valid descendant of lock holder -> accepted; credentials stored in memory.
   - Subsequent registration for same conversation ID replaces existing credentials atomically.
   - Releasing presence lock causes subsequent liveness checks to prune credentials.
3. **Delivery Execution & Environment Isolation (`tests/e2e_agy_delivery.rs`)**:
   - PATH stub for `agy` captures its argv and env:
     - Asserts `ANTIGRAVITY_LS_ADDRESS` and `ANTIGRAVITY_CSRF_TOKEN` are present in child env.
     - Asserts `ANTIGRAVITY_CSRF_TOKEN` is completely absent from command line argv.
     - Asserts envelope starts with `[xmsg] from=... message_id=...`.
     - Asserts exit 0 returns HTTP 202 `Accepted`.
   - Stub exiting with `"Unauthenticated"` -> returns HTTP 503 `credentials_stale`, marks registration stale.
   - Re-registration resets stale status; next delivery returns 202.
4. **Registration CLI Invariants (`tests/e2e_register_cli.rs`)**:
   - `xmsg register agy` with server stopped:
     - stdout equals `{"injectSteps":[]}\n`.
     - exit code equals 0.
   - Shipped binary test executing `env!("CARGO_BIN_EXE_xmsg") register agy`.

## 5. Parent Design Alignment & Known Boundaries
- Aligns directly with gist §9.1, §9.2, §9.4, §9.5.
- Credentials kept strictly in memory.
- No shell invocation (`sh -c`) for `agy agentapi send-message`.
- No modification of `den-ag-design` or `nix-config`.
- Real session presence locks are untouched.
