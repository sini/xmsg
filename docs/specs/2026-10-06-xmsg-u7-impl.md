## 1. Measured Red State at `8cfdee6`

1. **C1 (HTTP Lookalike Badge Forgery):**

   - At `8cfdee6`, `sanitize_from` performed case-folding and prefix checks against ASCII `"session:"` and `"session/"`.
   - Measured Red:
     - `session꞉evil` (U+A789 modifier letter colon) -> `202 Accepted` (`fromName="xmsg@test-host · session꞉evil"`)
     - `ｓｅｓｓｉｏｎ：evil` (fullwidth) -> `202 Accepted` (`fromName="xmsg@test-host · ｓｅｓｓｉｏｎ：evil"`)
     - `ѕession:evil` (Cyrillic dze U+0455) -> `202 Accepted` (`fromName="xmsg@test-host · ѕession:evil"`)
     - `session\u{a0}:evil` (NBSP collapses to space) -> `202 Accepted` (`fromName="xmsg@test-host · session :evil"`)
   - For an LLM reading recipient session context, these visual lookalikes carry identical badge weight to attested sessions.

2. **C2 (Agy Lock-Holder Takeover via POSIX lockf):**

   - At `8cfdee6`, `parse_locks_line` accepted both `FLOCK` and `POSIX`.
   - On the Linux kernel, POSIX `lockf` and `flock` coexist on the same inode, and `/proc/locks` listed the POSIX lock first in 18 of 20 trials.
   - Measured Red: `find_lock_holder` returned the attacker's PID `6666` instead of the genuine agy flock holder `4242`.

3. **C3 / Attested Badge Ambiguity:**

   - At `8cfdee6`, both Claude sessions and Pi sessions formatted as `xmsg@<host> · session:<name>`.
   - Measured Red: A Pi session registered with `sessionName: "boss"` and a Claude session named `"boss"` produced identical badges: `xmsg@h · session:boss`.

4. **Pi Queue Cap Status Code:**

   - At `8cfdee6`, queue full returned `AppError::InboxUnavailable`, yielding HTTP 502 instead of the specified HTTP 503.

5. **Minors at `8cfdee6`:**

   - Multibyte character straddling the `take()` bound caused UTF-8 `read_line` to fail with `InvalidData`, producing silent connection drop (`<EOF, no response>`).
   - Frame bound was `max_body + 4096`, causing valid JSON payloads with worst-case JSON escaping (e.g. `\u0001` expanding 6x) to be rejected as frame oversize.
   - `register.sock` had no idle timeout, waiting indefinitely on silent clients.
   - Re-reading peer PID starttime at accept only, not at use.
   - No automatic schema migration for `recipient_harness` on existing databases.

## 2. Architecture & Mechanisms

### 2.1 C1: Printable-ASCII Sender Enforcement on HTTP

1. **Rule:** In `src/inbox.rs`, `sanitize_from` enforces that unauthenticated HTTP sender names must consist **strictly of printable ASCII characters** (`0x20` to `0x7E`).
2. **Refusal of `:` and `/`:** Any occurrence of `:` or `/` in `req.from` causes immediate rejection with `400 Bad Request` (`AppError::BadSender("sender name cannot contain ':' or '/'")`).
3. **Non-ASCII Rejection:** Any character `< 0x20` or `> 0x7E` causes immediate rejection with `400 Bad Request` (`AppError::BadSender("sender name must contain only printable ASCII characters")`).
4. **Sanitization:** Quotes (`"`) and angle brackets (`<`, `>`) are stripped. Whitespace is collapsed and trimmed. If the trimmed result is empty or exceeds 64 characters, it is rejected.
5. **Guarantee:** Because `:` can never be supplied over HTTP, no HTTP caller can ever produce the badge separator `:`. The attested badge structure is unreachable from unauthenticated HTTP by mathematical construction.
6. **Documentation:** Delete the false NFKC normalisation claim from `README.md` and comments.

### 2.2 C3: Harness-Bound Attested Badges (`xmsg@<host> · <harness>:<name>`)

1. **Attested Badge Format:**
   The attested sender badge becomes:
   $$\\text{fromName} = \\text{"xmsg@"} \\parallel \\text{host_label} \\parallel \\text{" · "} \\parallel \\text{caller.harness} \\parallel \\text{":"} \\parallel \\text{cleaned_name}$$
   where `caller.harness` is `"claude"`, `"agy"`, or `"pi"`.
   Example: `xmsg@bitstream · pi:boss` vs `xmsg@bitstream · claude:boss`.
2. **Construction:**
   `inbox::sanitize_attested_from(host_label, harness, caller_name)` cleans `caller_name` (stripping quotes, brackets, control characters, collapsing whitespace), formats `{harness}:{cleaned_name}`, and caps total `fromName` at 64 Unicode chars.
3. **Double Prefix Fix:**
   In error messages and logging, ensure `caller.session_id` is formatted cleanly without prepending harness twice.

### 2.3 C2: Strict FLOCK-Only & Multiple-Holder Disambiguation in `agy.rs`

1. **FLOCK ADVISORY WRITE Only:**
   In `src/agy.rs`, `parse_locks_line` is updated to accept **only** `lock_type == "FLOCK"`. Any `POSIX` or non-`FLOCK` entry is ignored.
2. **Multiple Holder Ambiguity:**
   In `find_lock_holder` and `get_presence_lock_holder`:
   Collect all distinct PIDs holding a matching `FLOCK` on the inode.
   - If 0 holders: return `Ok(None)`.
   - If exactly 1 holder: return `Ok(Some(pid))`.
   - If > 1 distinct holders: return `Err(AppError::Ambiguous("multiple lock holders detected for presence lock"))`.
     The server never guesses or picks the first.

### 2.4 Pi Queue Cap: HTTP 503

1. In `src/http.rs`: When `storage::insert_pi_message` returns `false` (queue full $\\ge 100$), return `AppError::ServiceUnavailable("pi session message queue is full".to_string())`.
2. In `src/error.rs`: `ServiceUnavailable` maps to `StatusCode::SERVICE_UNAVAILABLE` (HTTP 503).
3. In `src/agent.rs`: Map queue full to `AppError::ServiceUnavailable`.

### 2.5 Minors

1. **Multibyte Frame Bound Handling (Minor 1):**
   In `agent.rs`, `pi.rs`, and `agy.rs`:
   Read bytes using a bounded buffer up to `max_frame = max_body * 6 + 4096`.
   If buffer exceeds `max_frame` without encountering `\n`, return `{"status":"error","error":"bad_request","detail":"frame exceeds maximum allowed size"}` and close stream.
   If `\n` is encountered within limit, decode bytes to UTF-8 using `std::str::from_utf8`. If invalid UTF-8, return clean error `{"status":"error","error":"bad_request","detail":"invalid utf-8"}`. Never drop the connection silently.
2. **Frame Bound Sizing (Minor 2):**
   Set `max_frame = state.max_body * 6 + 4096` across all socket line readers.
3. **`register.sock` Idle Timeout (Minor 3):**
   In `run_register_server`, wrap connection read loop / initial frame read in `tokio::time::timeout(Duration::from_secs(30), ...)`. If timed out, terminate the connection cleanly.
4. **Peer Starttime Verification at Use (Minor 4):**
   In `agent.rs`, before executing each action (`reply`, `send`), re-read `/proc/<peer_pid>/stat` starttime and verify it matches `initial_starttime`.
5. **Database Migration for `recipient_harness` (Minor 5):**
   In `storage::init_db`:
   Inspect table columns with `PRAGMA table_info(messages);`. If `recipient_harness` is absent, execute:
   `ALTER TABLE messages ADD COLUMN recipient_harness TEXT NOT NULL DEFAULT 'claude';`
