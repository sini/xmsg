[`agent-quota`](https://github.com/sini/nix-config/tree/main/pkgs/by-name/agent-quota) is a
standalone read-only command that reports remaining weekly usage for Antigravity, Codex and Claude
Code. The public `nix-config` repository packages it, and an operator can expose it on an xmsg
node through [`xmsg service exec`](/reference/cli-and-mcp/#xmsg-service-exec).

```sh
agent-quota
agent-quota --json
```

The command reads usage information that is available locally:

- Antigravity's local `/quota` command (its Gemini Models bucket);
- Codex rollout `rate_limits`;
- Claude Code's cached weekly utilization.

It reports missing data, and data that it cannot parse, as `unknown`. A cached figure is not a
live guarantee from the provider. The implementation says that these reads need no credentials.
It makes no model call.

## Running on the bus (`xmsg service exec`)

```sh
xmsg service exec --name agent-quota -- agent-quota --json
```

`agent-quota` itself does not open xmsg sockets. When enabled for a user (for example, as a
user service under systemd), [`xmsg service exec`](/reference/cli-and-mcp/#xmsg-service-exec)
registers `agent-quota@<node>`, runs `agent-quota --json` on each delivered request while ignoring
the request text, and replies with the command's UTF-8 JSON output. Service enablement is optional
per-user deployment configuration, and quota-based dispatch is not built into `xmsg`; check `list`
rather than assuming `send(to="agent-quota", ...)` has a registered recipient on every node.
