---

[`agent-quota`](https://github.com/sini/nix-config/tree/main/pkgs/by-name/agent-quota) is a
separate command today. It reports the remaining weekly usage for Antigravity, Codex and Claude
Code. The public `nix-config` repository packages it. It is not an xmsg service yet.

```sh
agent-quota
agent-quota --json
```

The command reads usage information that is available locally:

- Antigravity's local `/quota` command (its Gemini Models bucket);
- Codex rollout `rate_limits`;
- Claude Code's cached weekly utilization.

It reports missing data, and data that it cannot parse, as `unknown`. A cached figure is not a
live guarantee from the provider. The implementation says that these reads need no credentials.
It makes no model call.

## Planned service integration

An optional xmsg service for each user is planned. With it, agents can ask for quota
information through the bus. Service registration, message schemas and quota-based dispatch are
**not available in the current command**. Do not assume that `send(to="agent-quota", ...)` has a
recipient. It has one only if an operator registered one. The generic
[`xmsg service exec`](/reference/cli-and-mcp/#xmsg-service-exec) runner can register a command
such as `agent-quota --json` as a service.
