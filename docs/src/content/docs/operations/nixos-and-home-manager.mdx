title: NixOS & Home Manager
description: Installing and configuring xmsg, agent harness switches, and mTLS federation with the flake's Home Manager and NixOS modules.
---

The `github:sini/xmsg` flake provides two declarative modules:

- **`homeManagerModules.xmsg`** (also `homeManagerModules.default`): Installs `xmsg`. Runs
  `xmsg serve` as a user service (`systemd.user.services.xmsg` on Linux, `launchd.agents.xmsg` on
  macOS). Configures the MCP servers, plugins, extensions, skills and hooks for each harness.
- **`nixosModules.xmsg`** (also `nixosModules.default`): When federation is enabled, opens the
  federation TCP port in the system firewall.

## Minimal Home Manager import

```nix
{
  inputs.xmsg.url = "github:sini/xmsg";

  # In a Home Manager configuration:
  imports = [ inputs.xmsg.homeManagerModules.xmsg ];
  programs.xmsg.enable = true;
}
```

To install the CLI and the harness integrations without a local `xmsg serve` daemon, set
`programs.xmsg.server.enable = false`.

| Option | CLI Flag | Default |
|---|---|---|
| `programs.xmsg.package` | — | `inputs.xmsg.packages.${system}.default` |
| `programs.xmsg.server.httpSocket` | `--http-sock` | `$XDG_RUNTIME_DIR/xmsg/http.sock` |
| `programs.xmsg.server.agyExe` | `--agy-exe` (repeated) | `programs.antigravity-cli.package`'s `bin/agy` when `harnesses.agy.enable = true` |
| `programs.xmsg.server.codexExe` | `--codex-exe` (repeated) | `programs.codex.package`'s `bin/codex` when `harnesses.codex.enable = true` |
| `programs.xmsg.server.codexHome` | `--codex-home` (repeated) | `[ "${config.home.homeDirectory}/.codex" ]` |
| `programs.xmsg.server.svcExe` | `--svc-exe NAME=PATH` | `{ }` |
| `programs.xmsg.server.sessionsDirs` | `XMSG_SESSIONS_DIR` (colon-joined) | `[ "${config.home.homeDirectory}/.claude/sessions" ]` |
| `programs.xmsg.server.extraSessionsDirs` | appended to `sessionsDirs` | `[ ]` |

## Per-harness switches

Each switch under `programs.xmsg.harnesses.<name>.enable` installs the shared skill
(`nix/modules/skills/xmsg/SKILL.md`) and the integration for that harness:

- **`programs.xmsg.harnesses.claude.enable`:** Needs `programs.claude-code.enable = true`.
  - Adds `xmsg mcp` to `programs.claude-code.mcpServers`.
  - Installs the `xmsg` skill.
  - Adds the `list`, `send`, `reply`, `replies` and `inbox` permissions under
    `mcp__plugin_hm_xmsg__` and `mcp__xmsg__` (`permissionPrefixes`).
  - Configures `xmsg register claude --hook` (`PreToolUse`, `PostToolUse`, `SubagentStart`,
    `SubagentStop`).
- **`programs.xmsg.harnesses.codex.enable`:** Needs `programs.codex.enable = true`.
  - Links `${xdg.dataHome}/xmsg/bin/xmsg`.
  - Configures `programs.codex.skills.xmsg` and `programs.codex.settings.mcp_servers.xmsg`.
  - Enables `--codex-exe` and `--codex-home` on `xmsg serve`.
  - Exposes the read-only `programs.xmsg.harnesses.codex.{hooks,trustState,mcpServer}`.
- **`programs.xmsg.harnesses.agy.enable`:** Needs `programs.antigravity-cli.enable = true`.
  - Adds `xmsg mcp` to `programs.antigravity-cli.mcpServers`.
  - Installs the `xmsg` skill.
  - Writes `~/.gemini/config/hooks.json` (`PreInvocation`, `PreToolUse`, `Stop`).
- **`programs.xmsg.harnesses.opencode.enable`:** Writes `$XDG_CONFIG_HOME/opencode/plugin/xmsg.ts`
  and `opencode/skills/xmsg/SKILL.md` directly. It does not need an `opencode` module.
- **`programs.xmsg.harnesses.hermes.enable`:** Needs `services.hermes-agent`.
  - Links `extensions/hermes/` into `services.hermes-agent.extraPlugins`.
  - Adds `"xmsg"` to `settings.plugins.enabled` with `lib.mkAfter`.
  - Sets `settings.plugins.entries.xmsg.allow_gateway_injection = true`.
  - Installs `hermesHomeFiles."skills/xmsg/SKILL.md"`.
- **`programs.xmsg.harnesses.pi.enable`:** Writes `~/.pi/agent/extensions/xmsg-pi.ts` and
  `~/.pi/agent/skills/xmsg/SKILL.md`.

## Federation and peers configuration

```nix
programs.xmsg.server.federation = {
  enable = true;
  port = 7788;                        # --fed-listen 0.0.0.0:7788 (listenAddress)
  cert = ./xmsg-node.crt;             # --fed-cert (copied to the Nix store)
  key = "/run/secrets/xmsg-node.key"; # --fed-key (runtime path, never in the Nix store)
  reloadInterval = 30;                # --fed-reload-interval-secs
  peers = {
    # Pinned peer: set `pin = "sha256:..."` or `pinFromCert` to compute it at build time
    laptop = {
      address = "laptop.example.org:7788";
      pinFromCert = ./laptop.crt;
      allow = [ "send" "reply" "list" ];
    };
    # CA-signed peer: keyed by the node name derived from its single SPIFFE URI SAN
    "alice.workstation" = {
      address = "workstation.example.org:7788";
      ca = ./xmsg-root.crt;
      identities = [ "spiffe://example.org/host/workstation/user/alice" ];
      allow = [ "send" "reply" "list" ];
    };
  };
};
```

Each `peers` entry takes the same field names as an entry in the
[peers file](/concepts/federation/#entry-fields). `pinFromCert` is extra: it computes `pin` at
build time. These limits apply:

- **`address` has no default.** On a `leaf = true` entry the hub never dials the peer, so set
  `address = "";`.
- **No `default_route` option.** The module cannot mark a default route.
- **No `hub` block.** The module writes the bare-map form of the peers file, which cannot hold
  [hub admission](/concepts/federation/#hub-admission-hub).

The module has no option for a hand-written peers file. To use `default_route` or `hub`, write
the peers file yourself and run `xmsg serve --peers-file <path>` outside this module's service.

On NixOS, open the federation port in the firewall with `nixosModules.xmsg`:

```nix file=<rootDir>/nix/modules/nixos.nix#L1-L20
```
