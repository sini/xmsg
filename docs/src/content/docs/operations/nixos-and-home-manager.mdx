The `github:sini/xmsg` flake provides two declarative modules:

- **`homeManagerModules.xmsg`** (also `homeManagerModules.default`): Installs `xmsg`. Runs
  `xmsg serve` as a user service (`systemd.user.services.xmsg` on Linux, `launchd.agents.xmsg` on
  macOS). Configures the MCP servers, plugins, extensions, skills and hooks for each harness.
- **`nixosModules.xmsg`** (also `nixosModules.default`): Opens the federation firewall port
  (`programs.xmsg.federation`) and manages isolated system-user `xmsg serve` daemons
  (`services.xmsg.instances.<name>`).

## Minimal Home Manager import

```nix
{
  inputs.xmsg.url = "github:sini/xmsg";

  # In a Home Manager configuration:
  imports = [ inputs.xmsg.homeManagerModules.xmsg ];
  programs.xmsg.enable = true;
}
```

To install the CLI and the harness integrations without a local `xmsg serve` daemon, set
`programs.xmsg.server.enable = false`.

| Option | CLI Flag | Default |
|---|---|---|
| `programs.xmsg.package` | — | `inputs.xmsg.packages.${system}.default` |
| `programs.xmsg.server.httpSocket` | `--http-sock` | `$XDG_RUNTIME_DIR/xmsg/http.sock` (on macOS, the Darwin user temp directory, `getconf DARWIN_USER_TEMP_DIR`) |
| `programs.xmsg.server.agyExe` | `--agy-exe` (repeated, optional pin) | `programs.antigravity-cli.package`'s `bin/agy` when `harnesses.agy.enable = true` |
| `programs.xmsg.server.codexExe` | `--codex-exe` (repeated) | `programs.codex.package`'s `bin/codex` when `harnesses.codex.enable = true` |
| `programs.xmsg.server.codexHome` | `--codex-home` (repeated) | `[ "${config.home.homeDirectory}/.codex" ]` |
| `programs.xmsg.server.svcExe` | `--svc-exe NAME=PATH` | `{ }` |
| `programs.xmsg.server.sessionsDirs` | `XMSG_SESSIONS_DIR` (colon-joined) | `[ "${config.home.homeDirectory}/.claude/sessions" ]` |
| `programs.xmsg.server.extraSessionsDirs` | appended to `sessionsDirs` | `[ ]` |
| `programs.xmsg.server.stableExecutable` | — (macOS only) | `"${config.xdg.dataHome}/xmsg/serve/xmsg"` |

## macOS: a stable daemon executable

<Status id="nixos.module-options" />

macOS keys the Local Network permission to the executable's real path, so a daemon run straight
from the Nix store would re-prompt after every upgrade (and its first launch waits on the
prompt). The module keeps a stable copy so upgrades don't re-prompt: `launchd.agents.xmsg` runs
`programs.xmsg.server.stableExecutable`, a regular file (not a symlink) that activation replaces
when the package changes, by copying the new binary beside it and renaming it into place. When it
replaced an existing file it restarts the agent with `launchctl kickstart -k`, because the agent's
plist no longer changes across upgrades; a first install is started by launchd's `RunAtLoad`. The copy keeps the binary's own ad-hoc signature; nothing is re-signed. The
package stays in `home.packages`, so the copy's store libraries are not collected.

Set `stableExecutable = null` to run the store path directly, accepting a new prompt per
upgrade. The path must be absolute and outside the Nix store, and must differ from the Codex harness's `${config.xdg.dataHome}/xmsg/bin/xmsg`
link, which Home Manager owns. Linux is unaffected: the systemd unit runs the store path.

The agent writes its standard output (xmsg's log) to `~/Library/Logs/xmsg/stdout.log` and its
standard error (panics and early startup errors) to `~/Library/Logs/xmsg/stderr.log`, the same
files as the hand-written plist in [macOS](/getting-started/macos/). Activation creates
`~/Library/Logs/xmsg` (mode `0700`) before the agent loads, since launchd does not. The agent runs with `Umask` 0077, as the Linux unit does.

## Per-harness switches

Each switch under `programs.xmsg.harnesses.<name>.enable` installs the shared skill
(`assets/claude/xmsg/SKILL.md`) and the integration for that harness:

- **`programs.xmsg.harnesses.claude.enable`:** Needs `programs.claude-code.enable = true`.
  - Adds `xmsg mcp` to `programs.claude-code.mcpServers`.
  - Installs the `xmsg` skill.
  - Adds the `list`, `send`, `reply`, `replies` and `inbox` permissions under
    `mcp__plugin_hm_xmsg__` and `mcp__xmsg__` (`permissionPrefixes`).
  - Configures `xmsg register claude --hook` (`PreToolUse`, `PostToolUse`, `SubagentStart`,
    `SubagentStop`).
- **`programs.xmsg.harnesses.codex.enable`:** Needs `programs.codex.enable = true`.
  - Links `${xdg.dataHome}/xmsg/bin/xmsg`.
  - Configures `programs.codex.skills.xmsg` and `programs.codex.settings.mcp_servers.xmsg`.
  - Enables `--codex-exe` and `--codex-home` on `xmsg serve`.
  - Exposes the read-only `programs.xmsg.harnesses.codex.{hooks,trustState,mcpServer}`.
- **`programs.xmsg.harnesses.agy.enable`:** Needs `programs.antigravity-cli.enable = true`.
  - Adds `xmsg mcp` to `programs.antigravity-cli.mcpServers`.
  - Installs the `xmsg` skill.
  - Writes `~/.gemini/config/hooks.json` (`PreInvocation`, `PreToolUse`, `Stop`).
- **`programs.xmsg.harnesses.opencode.enable`:** Writes `$XDG_CONFIG_HOME/opencode/plugin/xmsg.ts`
  and `opencode/skills/xmsg/SKILL.md` directly. It does not need an `opencode` module.
- **`programs.xmsg.harnesses.hermes.enable`:** Needs `services.hermes-agent`.
  - Links `extensions/hermes/` into `services.hermes-agent.extraPlugins`.
  - Adds `"xmsg"` to `settings.plugins.enabled` with `lib.mkAfter`.
  - Sets `settings.plugins.entries.xmsg.allow_gateway_injection = true`.
  - Installs `hermesHomeFiles."skills/xmsg/SKILL.md"`.
- **`programs.xmsg.harnesses.pi.enable`:** Writes `~/.pi/agent/extensions/xmsg-pi.ts` and
  `~/.pi/agent/skills/xmsg/SKILL.md`.

## Federation and peers configuration

```nix
programs.xmsg.server.federation = {
  enable = true;
  port = 7788;                        # --fed-listen 0.0.0.0:7788 (listenAddress)
  cert = ./xmsg-node.crt;             # --fed-cert (copied to the Nix store)
  key = "/run/secrets/xmsg-node.key"; # --fed-key (runtime path, never in the Nix store)
  reloadInterval = 30;                # --fed-reload-interval-secs
  peers = {
    # Pinned peer: set `pin = "sha256:..."` or `pinFromCert` to compute it at build time
    laptop = {
      address = "laptop.example.org:7788";
      pinFromCert = ./laptop.crt;
      allow = [ "send" "reply" "list" ];
    };
    # CA-signed peer: keyed by the node name derived from its single SPIFFE URI SAN
    "alice.workstation" = {
      address = "workstation.example.org:7788";
      ca = ./xmsg-root.crt;
      identities = [ "spiffe://example.org/host/workstation/user/alice" ];
      allow = [ "send" "reply" "list" ];
    };
    # Fleet observation collector grant (`observeLabels` requires `"observe"` in `allow`)
    "owner.collector" = {
      address = "collector.example.org:7788";
      ca = ./collector-ca.pem;
      identities = [ "spiffe://xmsg/host/collector/user/owner" ];
      allow = [ "observe" ];
      observeLabels = true;
    };
  };
};
```

Each `peers` entry takes the same field names as an entry in the
[peers file](/concepts/federation/#entry-fields). `pinFromCert` is extra: it computes `pin` at
build time, and `observeLabels` (boolean, default `false`) emits `observe_labels = true` only
when enabled and requires `"observe"` in `allow`. These limits apply:

- **`address` has no default.** On a `leaf = true` entry the hub never dials the peer, so set
  `address = "";`.
- **No `default_route` option.** The module cannot mark a default route.
- **No `hub` block.** The module writes the bare-map form of the peers file, which cannot hold
  [hub admission](/concepts/federation/#hub-admission-hub).

The module has no option for a hand-written peers file. To use `default_route` or `hub`, write
the peers file yourself and run `xmsg serve --peers-file <path>` outside this module's service.

On NixOS, open the federation port in the firewall with `programs.xmsg.federation`:

```nix
programs.xmsg.federation = {
  enable = true;
  port = 7788;
};
```

## NixOS system services

`nixosModules.xmsg` provides `services.xmsg.instances.<name>` for running isolated system-user
`xmsg serve` daemons (`xmsg-<name>.service`). Each instance gets its own `0700` `RuntimeDirectory`
and `StateDirectory`, pinned sockets by default, `ProtectProc = "invisible"`, and an evaluation
assertion against TCP listeners unless `allowTcpListen = true` is set. See
[NixOS system-service instances](/operations/runtime-and-systemd/#nixos-system-service-instances) for
a usage example.

### `services.xmsg.instances.<name>` options

| Option | Type | Default | Purpose |
|---|---|---|---|
| `enable` | `bool` | `true` | Enable `xmsg-<name>.service`. |
| `package` | `package` | `packages.<system>.default` | `xmsg` package for this instance. |
| `user` | `str` | `"xmsg-<name>"` | System user owning runtime dir, state dir, and sockets. |
| `group` | `str` | `config.user` | Primary group for `xmsg-<name>.service`. |
| `home` | `nullOr str` | `"/var/lib/xmsg-<name>"` | `HOME` environment variable; `null` omits `HOME`. |
| `runtimeDir` | `str` (`/run/*`) | `"/run/xmsg-<name>"` | `RuntimeDirectory` (`0700`) and `XDG_RUNTIME_DIR`. |
| `stateDir` | `str` (`/var/lib/*`) | `"/var/lib/xmsg-<name>"` | `StateDirectory` (`0700`); holds `xmsg.db` (`XMSG_DB_PATH`). |
| `sessionsDirs` | `listOf (path \| str)` | `[ ]` | Directories for `XMSG_SESSIONS_DIR` (colon-joined). |
| `svcExe` | `attrsOf str` | `{ }` | `--svc-exe NAME=PATH` service admissions. |
| `sockets.http` | `nullOr str` | `"<runtimeDir>/xmsg/http.sock"` | `XMSG_HTTP_SOCK` pinned HTTP socket path. |
| `sockets.agent` | `nullOr str` | `"<runtimeDir>/xmsg/agent.sock"` | `XMSG_AGENT_SOCK` pinned agent socket path. |
| `sockets.register` | `nullOr str` | `"<runtimeDir>/xmsg/register.sock"` | `XMSG_REGISTER_SOCK` pinned registration socket path. |
| `allowTcpListen` | `bool` | `false` | Permit `--listen` / `XMSG_LISTEN` / `listen`. |
| `listen` | `nullOr str` | `null` | `XMSG_LISTEN` TCP address; requires `allowTcpListen = true`. |
| `extraArgs` | `listOf str` | `[ ]` | Extra CLI arguments appended to `xmsg serve`. |
| `extraEnvironment` | `attrsOf str` | `{ }` | Extra environment variables for `xmsg-<name>.service`. |
| `federation.enable` | `bool` | `false` | Enable `--fed-listen`, `--fed-cert`, `--fed-key`, `--peers-file`. |
| `federation.listenAddress` | `str` | `"0.0.0.0"` | Address the federation listener binds. |
| `federation.port` | `port` | `7788` | Federation listener port. |
| `federation.cert` | `path \| str` | *(required if enabled)* | `--fed-cert` PEM certificate path. |
| `federation.key` | `str` (runtime path) | *(required if enabled)* | `--fed-key` PEM private key path (never a store path). |
| `federation.reloadInterval` | `nullOr uint` | `null` | `--fed-reload-interval-secs` (null uses xmsg default `30`). |
| `federation.peers` | `attrsOf peer` | `{ }` | `--peers-file` entries (same schema as Home Manager `federation.peers`). |
| `federation.openFirewall` | `bool` | `false` | Open `federation.port` in `networking.firewall.allowedTCPPorts`. |

## Fleet observation collector

To run `xmsg observe-collector` as a managed user service (`xmsg-observe-collector.service` on
systemd, `xmsg-observe-collector` launchd agent on macOS), enable `programs.xmsg.observeCollector`:

```nix
programs.xmsg.observeCollector = {
  enable = true;
  stateDir = "/var/lib/xmsg/observe-collector";
  config = {
    client_cert = "/run/xmsg-observer/client.pem";
    client_key = "/run/xmsg-observer/client.key";
    auth = {
      issuer = "https://idp.example.org/oauth2/openid/observer";
      introspection_url = "https://idp.example.org/oauth2/token/introspect";
      subjects = [ "owner-subject" ];
      audience = "observer";
      hosted_client = "observer";
      lookup_client = "observer-lookup";
      lookup_secret_file = "/run/xmsg-observer/lookup-secret";
    };
    sources = [
      {
        node = "workstation.example.org";
        address = "workstation.example.org:7788";
        ca = "/etc/xmsg/node-ca.pem";
        identity = "spiffe://xmsg/host/workstation/user/alice";
      }
    ];
  };
};
```

`config` is rendered to JSON in the Nix store and passed via `--config`; `stateDir` defaults to
`${config.xdg.stateHome}/xmsg/observe-collector` and is passed via `--state-dir`. Keep private
keys and OIDC client secrets as runtime file paths rather than embedding them in Nix-store JSON.
See [Fleet Observer Operations](/operations/fleet-observer/) for the full collector schema.


## Planned enrollment with a managed installation

The [enrollment CA](/operations/enrollment-ca/) is configured through its CLI
flags and policy file. This change does **not** add a Home Manager/NixOS enrollment
option or automatic CA deployment aspect. Keep `root.key`, a machine's `fed.key`
and OAuth client secrets out of Nix-store values. Fleet and cluster issuers remain
separate from the enrollment root.

The current module also cannot render a hub block or select a hand-written peers
file. Install xmsg with the module, set `programs.xmsg.server.enable = false` if
managing the daemon yourself, and run the documented CLI under an operator-managed
service. Pass the flags from [the CA setup](/operations/enrollment-ca/#initialize-and-configure-the-hub),
or the client's printed `--enroll-state`, `--peers-file` and `--fed-listen` flags.
The existing runtime socket and harness configuration can still be used.

A platform facility such as systemd `LoadCredential` may deliver private files;
the portable form is the private file described in the guide. CA key ownership and
permission checks still apply. A declarative deployment aspect and real-provider
acceptance are separate operator-paced work; the module does not mint IdP
credentials or deploy a CA automatically.
