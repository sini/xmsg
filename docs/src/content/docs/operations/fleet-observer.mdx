The node export is available for explicitly authorized federation peers.
**The collector command and view are planned, not yet released.** They use the
node protocol below and the configuration described here. Actual ingress, owner
sign-in and deployment remain operator acceptance steps.

## Grant a collector access

A directly reachable exporter can grant one existing CA identity metadata-only
access in its peers file. This example allows only two endpoints on `owner.node`:

```json
{
  "peers": {
    "owner.collector": {
      "address": "collector.example.org:7788",
      "ca": "/etc/xmsg/collector-ca.pem",
      "identities": ["spiffe://xmsg/host/collector/user/owner"],
      "allow": ["observe"],
      "targets": [
        "11111111-1111-4111-8111-111111111111@owner.node",
        "guard@owner.node"
      ],
      "observe_labels": false
    }
  }
}
```

Use the exporter's real canonical node name in `targets`. The CA bundle and
collector certificate are existing operator-provided inputs. This grant does
not authorize send, reply or recipient discovery. Omit `targets` only when
node-wide export is intended; an empty array permits no event or descriptor data.
To permit labels, set `observe_labels: true` and request `labels=true`.

A hub can instead use a literal rule under its existing bundle-bound admission
patterns:

```json
{
  "pattern": "spiffe://xmsg/host/collector/user/owner",
  "allow": ["observe"],
  "targets": ["guard@owner.node"],
  "observe_labels": false
}
```

Place it before a broader matching rule: the first matching rule wins, with no
union of later grants. A wildcard observe rule is refused. Follow the existing
[peer reload procedure](/operations/runtime-and-systemd/) and reconnect the
observer after a peer-policy reload. A pre-reload TLS connection cannot continue
exporting under its old grant; a reload during a read discards the prepared page.

## Read retained metadata

Send these HTTP/1.1 requests over verified mTLS to `owner.node`'s existing
`--fed-listen` listener, using the authorized collector identity:

```http
GET /fed/v2/observe/events?v=1&after=0&limit=100 HTTP/1.1
Host: owner.node:7788

```

This begins at retained history, rather than selecting the local Unix API's
recent tail. Omitted `after` also means `0` on the export. To continue, take
`epoch`, `scope` and `next` from the response and send them as `epoch`, `scope`
and `after`. Positive `after` requires both cursor fields; `scope` is 64 lowercase
hexadecimal characters. A scope fingerprint detects policy changes and is not
an authorization token. Keep `labels` consistent across continuation requests.

```http
GET /fed/v2/observe/snapshot?v=1&labels=false HTTP/1.1
Host: owner.node:7788

```

The snapshot describes bounded cached registrations, not current process health
or a complete fleet inventory. Neither request has a body. Normal HTTP and MCP
do not expose these routes. The existing Unix `/v1/observe/events` remains private
to the node's UID.

See the [wire reference](/reference/http-and-sockets/#planned-node-observation-export)
for schemas and bounds. Preserve `gaps`, epoch resets and `scope_changed` visibly.
An empty event list can mean policy filtering; it is not proof of inactivity.
On timeout or unavailability, keep any historical data visibly stale rather than
reporting a successful empty history. Reconnect after reload and begin a new
backfill when the policy scope changes.

## Configure the collector

The collector starts separately from `xmsg serve`. It uses its own metadata
database and does not initialize bus storage, enrollment or harness registries.
Provide the client certificate/key and each exporter's existing trust inputs;
it does not enroll nodes or create credentials.

A JSON configuration has one fixed introspection provider and at most 64 sources:

```json
{
  "client_cert": "/run/xmsg-observer/client.pem",
  "client_key": "/run/xmsg-observer/client.key",
  "auth": {
    "issuer": "https://idp.example.org/oauth2/openid/observer",
    "introspection_url": "https://idp.example.org/oauth2/token/introspect",
    "subjects": ["owner-subject"],
    "audience": "observer",
    "hosted_client": "observer",
    "lookup_client": "observer-lookup",
    "lookup_secret_file": "/run/xmsg-observer/lookup-secret"
  },
  "sources": [
    {
      "node": "owner.node",
      "address": "node.example.org:7788",
      "ca": "/run/xmsg-observer/node-ca.pem",
      "identity": "spiffe://xmsg/host/node/user/owner",
      "labels": false
    },
    {
      "node": "worker.pod",
      "outbound_only": true
    }
  ]
}
```

Use canonical node names. CA identities are literal and must derive the configured
node name; a pinned source uses `pin` instead of `ca` and `identity`. Relative file
paths resolve against the configuration file. `outbound_only` entries are shown
as unsupported and never polled through custody or opened to inbound traffic.

Planned command:

```sh
xmsg observe-collector --config collector.json --state-dir ./observer-state --listen 127.0.0.1:9428
```

The default listen address is `127.0.0.1:9428`. Non-loopback listeners require
`web_tls: { "cert": "server.pem", "key": "server.key" }`; loopback may use it too.
The state directory must be owned by the running UID and mode 0700, with a regular
mode-0600 database. Unsafe existing paths are refused rather than repaired.

## Admit the owner

Configure ingress OIDC to enforce the exact issuer/subject allowlist, strip public
identity headers and forward the original access token as `Authorization: Bearer`.
The collector independently introspects that token for every request. Direct backend
requests have the same owner boundary; `X-Forwarded-User` and similar headers do not
provide identity.

It requires active status, exact issuer, an allowed subject, the configured audience
as a string or singleton array, and the configured client from `client_id` or `azp`
(equal when both exist). Expiry must be a future unsigned integer; optional
not-before must be an unsigned integer at or before now. Missing claims and provider
failure refuse access. No positive authorization cache or browser token store exists.

Provider TLS uses native roots, with optional `auth.provider_ca` for an operator CA.
Basic lookup credentials are optional but must be supplied as a pair. Kanidm 1.11.2
does not authenticate introspection callers: its lookup secret is not the owner
access boundary. The bearer and verified claims provide that boundary. A provider's
UI logout is not assumed to invalidate an otherwise active token.

Ingress forwarding/allowlisting, actual owner IDs, client registration, server TLS
and namespace policy must be verified on the deployed versions by the operator.
Fixture tests do not claim production compatibility or real owner sign-in.

## Read the view

Only `GET /` returns the owner view. `GET /health` without a query returns fixed
availability text and no cached node information. The view has numeric `node` and
`page` filters: nodes use their zero-based position in canonical-name sorted
inventory, pages are 0–49. Unknown, duplicate or out-of-range fields are refused.
There is no browser-supplied node address, body-detail route or action control.

The page refreshes every five seconds. Shapes distinguish cached sessions and
services; an unknown kind stays unknown. Exchange lanes report actual endpoint
references and outcomes, not network hops or evidence that an agent read a message.
Source epoch/sequence order, source time and collector receipt age remain separate.
Partial catalogs, backfill, gaps and truncation are explicit.

After each collector restart, stored history stays hidden until a node returns a
valid current scope. The view says **“history hidden until this node answers”**;
an empty timeline is not substituted for that state. Denial or a scope change
masks old data before attempting a purge, and a failed purge keeps it hidden.
Once validated in the current process, temporarily unreachable nodes may show
retained data marked stale.

## Retention and bounds

Per node, the cache retains at most seven days, 10,000 events and 16 MiB of accounted
metadata, including its latest snapshot. It does not accumulate snapshot archives.
Page records and their cursor commit together. Replays do not duplicate retained
rows or refresh their retention age; expiry also runs while polling is idle.
Retention uses observation time capped by collector receipt time, not a future
source timestamp that could indefinitely extend an old capture.

The SQLite file has a separate physical ceiling of 32 MiB per configured node plus
64 MiB reserve. Rollback journaling is separately bounded; memory-only temporary
storage and disabled cache spill have a RAM cost. These are managed file-length
bounds, not exact filesystem allocation or forensic erasure guarantees. Physical
storage exhaustion can stop ingestion before the logical limit; it is visible and
cannot commit a cursor without its page.

Polling uses at least two seconds between requests to one node, one request in
flight per node and eight globally, with a five-second whole-RPC deadline. Rate
limits back off rather than becoming successful empty histories. The HTTP view is
bounded to 64 connections, eight requests and a five-second preparation budget;
introspection has a two-second deadline and 64 KiB streamed-response cap. Bearers
are at most 8 KiB and request headers 16 KiB. HTML, including SVG, is at most 4 MiB;
rows and endpoint objects are bounded and truncation is shown.

Labels require source grant and collector request opt-in. Dynamic HTML/SVG text is
escaped, scripts are disabled by CSP, and responses use no-store and nosniff. No
message body, transcript, cwd, path, environment or credential field is stored or
rendered. Authorized compromised exporters or collectors remain trusted-component
compromises; metadata identifiers and opted-in labels are not a covert-data filter.
