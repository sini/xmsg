---
title: Hermes
description: Integrating Hermes Agent with xmsg via the extensions/hermes plugin.
---

Hermes loads the `xmsg` plugin (`extensions/hermes/plugin.yaml` and
`extensions/hermes/__init__.py`) from `$HERMES_HOME/plugins/` when `plugins.enabled` includes
`"xmsg"`. As for `opencode`, the Hermes plugin holds one multiplexed `register.sock` connection
for each Hermes process.

## Registration and tools

- **Registration:** A session registers at the first `pre_llm_call` hook or `xmsg` tool call
  that carries its `session_id`.
- **Delegates (`delegate_task`):** The `pre_llm_call` of a `delegate_task` subagent names its
  parent. The subagent acts as its root conversation `P`. It does not bind a separate
  sub-address.
- **Tools (`xmsg` toolset):** The plugin gives `xmsg_list`, `xmsg_send`, `xmsg_reply` and
  `xmsg_replies`. It sends them as frames on `register.sock` under the calling `session_id`. By
  default, Hermes puts plugin tools behind its Tool Search bridge (`tools.tool_search`). Thus
  models find and call them through `tool_search` and `tool_call`.

## Session lifecycle and compaction

- **Ending a session (`on_session_finalize`):** These actions release the session's address
  (`410 gone`): you close a desktop session, run `/new`, or exit the CLI. A late tool call from an
  ended session's background delegate returns `gone`. It does not register the old session again.
- **Switching sessions in the CLI:** `/new` ends the old session and registers the new one
  (`on_session_reset`). `/resume` and `/branch` start no plugin hook. For them, the plugin sees
  the changed `session_id` on the next hook, tool call or push. It then releases the old address.
  Thus xmsg never puts one session's message into another session.
- **Compression (`continues`):** Hermes's default in-place compaction keeps `session_id` and its
  `xmsg` address. With `compression.in_place: false`, compression makes a new `session_id`. The
  plugin then reads `SessionDB(read_only=True).get_compression_chain`. It sends a `continues`
  frame on `register.sock`, which moves the `xmsg` address to the new session ID.

## Push delivery and busy modes

- **Classic CLI:** While a turn runs, a delivered message goes through the CLI's busy-input
  handler. `display.busy_input_mode` (or `/busy`) sets the mode:
  - `queue` runs the message as the next turn.
  - `interrupt` redirects the running turn.
  - `steer` puts the message in after the current tool call.

  When the session is idle, the message starts a new turn.
- **TUI and desktop host:** Hermes's `inject_message` queues incoming messages on the session in
  all busy modes. Thus a notification never cancels work in progress. This needs
  `plugins.entries.xmsg.allow_gateway_injection: true` in the Hermes settings.
- **Acknowledgments:** The plugin sends `ack` only after Hermes accepts the message.

## Home Manager switch

Set `programs.xmsg.harnesses.hermes.enable = true`. This needs `services.hermes-agent`. The
switch links the plugin into `services.hermes-agent.extraPlugins`, adds `"xmsg"` to
`settings.plugins.enabled`, enables `allow_gateway_injection` and installs the `xmsg` skill. See
[NixOS & Home Manager](/operations/nixos-and-home-manager/#per-harness-switches).
