An interactive Antigravity (`agy`) session runs an internal language server on a loopback port.
An ephemeral CSRF token for each session protects it. Two variables hold these values:
`ANTIGRAVITY_LS_ADDRESS` and `ANTIGRAVITY_CSRF_TOKEN`. Antigravity shows them only inside the
interactive harness and the `run_command` subshells that it starts. MCP server children and
external hooks do not get them. Thus `xmsg` registers an Antigravity session in two stages.

## Two-stage registration lifecycle

1. **Stage 1 — Identity at MCP start:**
   When `xmsg mcp` starts as an `agy` child, `xmsg serve` walks its ancestor process chain. It
   looks for a trusted `--agy-exe` binary with an open file descriptor to
   `~/.gemini/antigravity-cli/presence/<conversation_id>.lock`. The match uses the canonical
   `(dev, ino)`. On Linux, xmsg also checks for exclusive `FLOCK` ownership in `/proc/locks`.
   The session is then immediately addressable by its conversation UUID (`registered: false`).
   Messages to it wait in `agy_pending_messages` (`outcome: "queued"`).
2. **Stage 2 — Credential capture & FIFO flush:**
   Then `ANTIGRAVITY_LS_ADDRESS` and `ANTIGRAVITY_CSRF_TOKEN` are registered. The Linux in-process
   command watcher can do this automatically. Otherwise the model runs `xmsg register agy`. Then
   `xmsg` does three things:
   - It stores the credentials only in memory.
   - It admits the subagents that the parent's `.system_generated/subagents/*.json` descriptors
     name. A successful registration response means those child bindings are ready, so a caller
     can address `<parent>/kid` at once, without a retry.
   - After that, it delivers all queued messages in FIFO order (`outcome: "delivered"`). A
     successful registration does not mean that delivery is complete.

## Linux command watcher (Arm A) vs. Hook prompt (Arm B′)

- **Linux In-Process Command Watcher (Arm A):** An attested `agy` conversation can hold its
  presence lock without registered push credentials. During that time, `xmsg serve` scans the
  attested `agy` process's descendant tree (`/proc/<pid>/task/<tid>/children`) every 100 ms. When
  a descendant tool command runs, `xmsg` checks its start time before and after it reads
  `/proc/<pid>/environ`. It copies **only** `ANTIGRAVITY_LS_ADDRESS` and `ANTIGRAVITY_CSRF_TOKEN`
  into memory. While Arm A watches on the first turn, the `PreInvocation` hook does nothing (it
  prints `{}`).
- **Darwin & Sandbox Fallback (Arm B′):** Arm B′ applies on macOS, in a Linux sandbox where
  `/proc` is not readable, and when a turn ends without a shell command. There,
  `xmsg register agy --hook --event pre-invocation` returns an `ephemeralMessage`. The message
  tells the model to run `xmsg register agy` first.

## Hook configuration (`~/.gemini/config/hooks.json`)

Configure `PreInvocation`, `PreToolUse`, and `Stop` in `~/.gemini/config/hooks.json`:

```json
{
  "xmsg-register": {
    "PreInvocation": [
      {
        "type": "command",
        "command": "xmsg register agy --hook --event pre-invocation"
      }
    ],
    "PreToolUse": [
      {
        "matcher": "call_mcp_tool|mcp_xmsg_.*",
        "hooks": [
          {
            "type": "command",
            "command": "xmsg register agy --hook --event pre-tool-use",
            "timeout": 5
          }
        ]
      }
    ],
    "Stop": [
      {
        "type": "command",
        "command": "xmsg register agy --hook --event stop",
        "timeout": 5
      }
    ]
  }
}
```

### Subagents (`<P>/<child_uuid>@<node>`)

A registered parent session `P` can start a subagent with `invoke_subagent`. Then the hooks do
this:

- **`PreInvocation`:** Admits the child from `P`'s
  `brain/<P>/.system_generated/logs/transcript.jsonl`. Binds `<P>/<child_uuid>@<node>`. Marks the
  child's turn active. Prints `{}`, so the child never gets a registration prompt.
- **`PreToolUse`:** Adds `as_agent: <conversationId>` to `call_mcp_tool` / `mcp_xmsg_*` calls.
  Thus `send`, `reply` and `inbox` act as `<P>/<child_uuid>@<node>`, or as `P` when the parent
  calls them.
- **`Stop`:** Clears the subagent's active turn. Moves the remaining messages in its turn mailbox
  to the parent `P`, with a `to=<P>/<child_uuid> agent_id=<child_uuid>` header.

## Server restart resilience

`xmsg serve` can restart while an `agy` session is open. Then the running `xmsg mcp` child
connects to `agent.sock` again, with backoff. This restores the stage 1 registration. Incoming
messages queue safely until the next turn registers the push credentials again.

## Home Manager switch

Set `programs.xmsg.harnesses.agy.enable = true`. This needs `programs.antigravity-cli.enable = true`.
The switch configures the MCP server, the skill, `--agy-exe` and `~/.gemini/config/hooks.json`.
See [NixOS & Home Manager](/operations/nixos-and-home-manager/#per-harness-switches).
