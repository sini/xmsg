Claude Code connects to `xmsg` in three ways:

- automatic session discovery (`~/.claude/sessions`);
- the `xmsg mcp` server, which gives the session the xmsg tools;
- `xmsg register claude --hook`, which gives delegated [subagents](/glossary/#subagent) their
  sub-addresses.

## Session discovery (`--sessions-dir`)

By default, `xmsg serve` finds live Claude Code sessions in `~/.claude/sessions`. A multi-tenant
setup can have two or more `CLAUDE_CONFIG_DIR` trees under the same UID. For it, give one
`--sessions-dir` flag for each directory, or colon-separated paths in `XMSG_SESSIONS_DIR`:

```bash
xmsg serve --sessions-dir /path/one/sessions --sessions-dir /path/two/sessions
# or colon-separated:
export XMSG_SESSIONS_DIR="/path/one/sessions:/path/two/sessions"
xmsg serve
```

- **Liveness verification:** `xmsg` checks that the process is live and that its start time has
  not changed. On Linux, it uses `/proc/<pid>/stat`. On macOS, it uses `proc_pidinfo`, and the
  result must match, to the second, the UTC `ps -o lstart` time that Claude Code records as
  `procStart`.
- **Instance claims & forks (`X~2`):** The same conversation ID `X` can be active in two or more
  processes or directories. Then the first live process that xmsg sees claims plain `X`. Each
  later process gets the next [fork suffix](/glossary/#fork-suffix) `X~2`, `X~3`, … in
  `instance_claims`. Each process gets one fork notice.
- **Parked queue & cross-machine handoff:** When a Claude Code process exits, its conversation ID
  stays [`parked`](/glossary/#parked) for the reply TTL (`7 days` by default). Messages to it
  wait in SQLite. xmsg delivers them when the conversation resumes. If the conversation resumes on
  another machine of the same user, the messages move there over `POST /fed/v2/handoff`.

## MCP configuration

Add `xmsg mcp` to your Claude Code `mcpServers` configuration:

```json
{
  "mcpServers": {
    "xmsg": {
      "command": "xmsg",
      "args": ["mcp"]
    }
  }
}
```

A responder-only session only answers incoming messages. It does not find recipients or start
new exchanges. For such a session, pass `--reply-only`. Then the server gives only `reply` and
`replies`.

## Subagent hooks (`xmsg register claude --hook`)

The `Agent` tool starts Claude Code subagents in the parent's process. They share the parent's
`session_id` and MCP server process. `xmsg register claude --hook` connects four Claude Code hook
events to `agent.sock`. Thus each subagent gets a delegated sub-address (`<P>/<name>@<node>` and
`<P>/<agent_id>@<node>`):

- **`SubagentStart`:** Sends `{"action":"subagent","event":"start","agent_id":…,"agent_type":…}`
  on `agent.sock`. This binds `<P>/<agent_id>@<node>` under the parent `P` and marks the
  subagent's turn active.
- **`PostToolUse` (matcher `^(Agent|SendMessage)$`):**
  - On `Agent`, it reads `tool_input.name` and `tool_response.agentId` (or
    `subagents/agent-<id>.meta.json` next to `transcript_path`). Then it sends a `subagent` `bind`
    frame. Thus both `<P>/<name>@<node>` and `<P>/<agent_id>@<node>` resolve to the subagent.
  - On `SendMessage`, `tool_input.to` can name a bound subagent whose in-memory teammate channel
    is unreachable after a restart. Then the hook queues the message in the subagent's `xmsg`
    mailbox.
- **`PreToolUse` (matcher `^mcp__(plugin_hm_)?xmsg__(send|reply|inbox|list|replies)$`):** Returns
  `hookSpecificOutput.updatedInput` with `as_agent` set. For a call from a subagent, `as_agent`
  is the hook payload's `agent_id`. For a call from the parent, it is `session_id`. This replaces
  any value that the model gave.
- **`SubagentStop`:** Sends `{"action":"subagent","event":"stop","agent_id":…}` on `agent.sock`.
  This clears the active turn. Then later messages to `<P>/<child>@<node>` go to the parent `P`,
  with a `to=<P>/<child> agent_id=<agent_id>` header.

## Manual setup without Home Manager

After installing xmsg, run `command -v xmsg` and use that **absolute path** in the
configuration below. `/absolute/path/to/xmsg` is a placeholder, not a command to copy unchanged.
The daemon and Claude Code must run as the same user, with the same runtime directory.

Merge this entry into your project's `.mcp.json` (or the equivalent Claude Code MCP
configuration). Preserve any existing servers:

```json
{
  "mcpServers": {
    "xmsg": {
      "command": "/absolute/path/to/xmsg",
      "args": [
        "mcp"
      ]
    }
  }
}
```

Merge these hooks into `~/.claude/settings.json`, preserving your other settings and hook
entries. If you use a different `CLAUDE_CONFIG_DIR`, use its settings file and give the daemon
its corresponding `--sessions-dir`. Each command below must contain your installed path:

```json
{
  "hooks": {
    "SubagentStart": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "/absolute/path/to/xmsg register claude --hook"
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "^(Agent|SendMessage)$",
        "hooks": [
          {
            "type": "command",
            "command": "/absolute/path/to/xmsg register claude --hook"
          }
        ]
      }
    ],
    "PreToolUse": [
      {
        "matcher": "^mcp__xmsg__(send|reply|inbox|list|replies)$",
        "hooks": [
          {
            "type": "command",
            "command": "/absolute/path/to/xmsg register claude --hook"
          }
        ]
      }
    ],
    "SubagentStop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "/absolute/path/to/xmsg register claude --hook"
          }
        ]
      }
    ]
  }
}
```

If the executable path contains spaces, shell-quote it inside each hook command; MCP's
`command` field itself is a path, not a shell command. This matcher is for a direct MCP server
named `xmsg`. A plugin registration can use a different tool prefix; match the actual prefix as
the Home Manager configuration does.

Restart Claude Code after changing its MCP configuration, then use its xmsg `list` tool. A
running session should appear in `xmsg list`. Use the [local service example](/getting-started/ubuntu/)
to test the bus before debugging harness discovery. The configuration carries no xmsg secret
or account credentials. Claude Code itself still needs its usual independent setup.

## Home Manager switch

In Home Manager, set `programs.xmsg.harnesses.claude.enable = true`. This installs the MCP
server, the `xmsg` skill, the tool permission rules under `mcp__plugin_hm_xmsg__` and
`mcp__xmsg__`, and all four subagent hooks. See
[NixOS & Home Manager](/operations/nixos-and-home-manager/#per-harness-switches).
