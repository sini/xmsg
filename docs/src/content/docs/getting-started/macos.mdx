`xmsg` supports `aarch64-darwin`. macOS CI (`.github/workflows/macos.yml`) runs on each push and
pull request that changes code.

## Platform specifics on Darwin

- **Runtime directory:** When `XDG_RUNTIME_DIR` is not set on macOS, `xmsg` finds its `0700`
  runtime directory with `getconf DARWIN_USER_TEMP_DIR`.
- **Peer credentials:** The Unix sockets (`http.sock`, `agent.sock`, `register.sock`) check the
  peer UID with `getpeereid` and the peer PID with `LOCAL_PEEREPID`. They check process start
  times with `proc_pidinfo`.
- **Home Manager (`launchd`):** On Darwin, import `inputs.xmsg.homeManagerModules.xmsg`. It
  configures `launchd.agents.xmsg` to run `xmsg serve`. See
  [NixOS & Home Manager](/operations/nixos-and-home-manager/).
- **Antigravity on macOS:** XNU does not show `flock(2)` owner PIDs to unprivileged processes.
  Thus on macOS, xmsg checks `--agy-exe` (`proc_pidpath`) and the open descriptor's vnode
  `(vst_dev, vst_ino)`. It uses the `PreInvocation` hook (`Arm B′`) to start
  `xmsg register agy`. See
  [Antigravity](/harnesses/antigravity/).
- **Codex on macOS:** The writer-lock lease watch uses `kqueue` on an `O_EVTONLY` descriptor, not
  `inotify`. Descriptor paths come from `fcntl(F_GETPATH)`. xmsg reads the lock holder with
  `proc_pidinfo`. See [Codex](/harnesses/codex/).

## What macOS CI exercises

The macOS job builds and tests on Apple Silicon:

- the `xmsg` package, whose build runs the full `cargo test` suite, including macOS-only tests
  for Claude Code start times and the Codex `kqueue` lease watch;
- the shared service client checks;
- the Codex hook check, which drives a real `codex` binary against `xmsg`;
- the compatibility check against older `xmsg` releases.

The Pi, opencode, Hermes and Antigravity hook checks run only on Linux. On macOS, the Rust test
suite tests the daemon side of those integrations. But no check drives the real harness.
