The standalone `xmsg-executor` library lives in `extensions/executor/`. This
foundation contains data contracts, bounded ACP framing and test-only fake
fixtures, a private Unix control handler and a separate journal.
**Real lifecycle calls fail closed** while caller-attribution qualification
is unavailable. The metadata-only bridge exists, but enables no runtime tuple
in this release. There is no installed executable or real harness integration.
Supervisor subprocess fixtures use a fake ACP backend only. The [teams runtime](/concepts/teams/) remains planned.
The default xmsg installation does not acquire an executor dependency.

## Developer checks

From a source checkout:

```sh
cargo test --manifest-path extensions/executor/Cargo.toml --locked
cargo clippy --manifest-path extensions/executor/Cargo.toml --locked --all-targets -- -D warnings
cargo fmt --manifest-path extensions/executor/Cargo.toml -- --check
```

The package has its own manifest, lockfile and test inventory/census. These checks
exercise fake peers and contracts; they do not start Claude, Codex or Antigravity
or qualify a native effect. No adapter package installation or credentials are
needed for them.

## Contract boundary

`protocol::ControlRequest` separates `version`, `request_id`, `verb`, `target`,
`args` and `deadline`. Targets distinguish team, session, execution and turn.
Dispatch keeps the harness and model separate and carries a locally resolved,
cross-host-shaped executor/workspace descriptor.

The uniform verbs are `dispatch`, `send`, `steer`, `interrupt`, `resume`, `stop`,
`status`, `result` and `approve`. Best-effort “send, prefer live” is distinct from
strict steer. Authorization, durable admission, native submission and observed
effect are separate receipt concepts. The DTOs do not authenticate callers,
enforce grants, persist a journal or perform these operations.

Future lifecycle calls require peer UID plus an owner-configured verb/target
grant tied to the attested caller for that call. There are no per-agent minted
control credentials. Separate credentials belong only to owner administration
and the human-decision channel. An ordinary bus message or a field claiming to
be a parent/human is not a control grant.

## Pins are not conformance evidence

`capability::PinManifest` and `fixtures/pins.json` record these planned ACP v1
tuples:

| Harness | Adapter | Native runtime |
| --- | --- | --- |
| Claude | claude-agent-acp 0.108.0 | Claude 2.1.327 |
| Codex | codex-acp 2.7.0 | Codex 0.169.1 |
| Antigravity | native agy ACP | agy 1.5.10 |

Every real-pin capability starts **unproven**. Capability states are `unproven`,
`proven` and `not_supported`; evidence classes distinguish `fake_only` from
`pinned_runtime`. A passing fake fixture is never a native-runtime proof. In
particular, it establishes neither strict live steering nor cancellation
quiescence, resume, reviewer isolation or preservation of human-only approval
subtypes.

SAFE human-only is the default profile contract. The owner-only UNSAFE profile
is representable for every pin, with per-protection states `proved_retained`,
`unknown` and `lost`; the initial fixture records unknown protections. That is
not an implemented permissions-off launcher or a claim that safeguards survive.
No agent may select/edit that profile in the future control service.

`framing::MAX_FRAME_BYTES` bounds frame decoding. Structured native permission
requests remain distinct from failed tool status and content. All child-supplied
text and metadata remain data. Harness-owned child observations do not become
managed dispatches or additional prompts.

## Fail-closed control journal

<Status id="teams.control-journal" />

`control::ControlService` is a library boundary, not an installed daemon or a
new core xmsg endpoint. The embedding application owns each private Unix
connection. `unix::bind_private_socket` requires a private directory and creates
a private socket. The lifecycle, owner and human connection handlers are
separate; each consumes one call. There is no `xmsg-executor serve` command.

The lifecycle path checks the kernel peer UID and requests an attested
principal for that specific call. The production attestor is deliberately
unavailable, so a valid same-UID lifecycle request returns
`attestation_unavailable`; a caller of the wrong UID is rejected. Grant-success
paths use a sealed, test-only attestor in unit tests. No request field, parent
relationship, copied bus origin, ambient MCP process or owner/human credential
substitutes for lifecycle attribution. The opt-in bridge below adds no enabled production tuple.

Owner-configured grants name a principal, verb and target. The journal keeps
authorization, durable admission and observed effect distinct. The same
principal/request ID and canonical resolved input replays a **historical**
receipt, not fresh authority or a second admission. Different input reusing the
ID conflicts. Generation/turn, current policy/profile and deadline fences apply
before a new admission. A denied request does not become accepted simply
because policy changes later.

The executor database is separate from the bus database, in a private directory.
It records requests, sessions, admissions, policy/profile revisions and audit
metadata. Fake pending requests test human-decision fencing and single use;
they are not a real ACP approval relay or a claim that native human-only
provenance is preserved. The supervisor fixtures launch only owned fake subprocesses. No bus message
becomes control, and no real harness is invoked.

### Privileged connection contracts

`ControlService::handle_lifecycle_connection` accepts one strict JSON line.
`handle_owner_connection` and `handle_human_connection` first accept a bounded
newline-terminated proof, then a strict JSON line. Their separately provisioned
proofs are distinct, 32–128 bytes without CR/LF; proofs never belong in prompts,
bus messages, command arguments or logs. This library does not mint or install
credentials. Same UID alone is not owner or human authority.

Owner policy replacement/profile revocation requires the owner channel, with
revision checks and atomic configuration validation. Human decisions require
the human channel and exact still-pending request binding. Their credentials
do not bypass lifecycle attribution or grant checks. These controls do not
claim isolation from arbitrary same-UID code.


## Supervisor and workspace boundary

<Status id="teams.supervisor" />

The crate-private supervisor foundation consumes journal-derived launch authority, not
serialized receipts supplied by a caller. Immediately before launch it rechecks
the current grant, profile, generation and resource budget. A durable launch
intent and exclusive execution lock prevent concurrent claims or reconnects
from starting a second execution. Reconnect reconciles identity and progress;
it does not replay a prompt or silently start a replacement.

An ambiguous or lost owner is `unknown`, with its resource slot still consumed.
A saved PID alone is neither ownership nor proof of death. Stop applies only
to an owned process group; it is not an interrupt fallback. In this stage, a
stop attempt remains `unknown` and retains the slot and workspace: reaping the
direct backend does not prove that every descendant has stopped. The supervisor
bounds startup and connection I/O within the execution wall-time budget and
checks its held backend before reporting it running.

Workspace preparation uses an owner-bound repository, an immutable base and an
approved destination root. It revalidates repository identity, HEAD and worktree
inventory before the owned effect. It does not copy a dirty checkout or harness
authentication files. Cleanup preserves modified work rather than silently
discarding it.

### Runtime socket location

The internal `OwnerRuntimeConfig::for_user` chooser separates socket storage
from the journal and workspace. On Linux it prefers an absolute
`XDG_RUNTIME_DIR` owned by the current UID, mode `0700`, with no symlink
components. A configured but invalid value is refused. On macOS, or Linux
without that variable, it selects a short per-user namespace under canonical
`/tmp`. The namespace is created only after backend availability and genuine
admission checks; pre-existing unsafe directories are refused rather than
chmodded or taken over.

`OwnerRuntimeConfig::new(runtime_root, ...)` preserves an explicit root. Before
creating an execution directory or workspace, the controller checks the entire
derived Unix socket path against the platform capacity, including space for its
terminating NUL (104 bytes on macOS). A typed error reports the platform, byte
count and capacity. Use the short `for_user` chooser or supply a shorter
`runtime_root`; this stage adds no CLI configuration flag. Long state or
workspace paths are not themselves shortened.

### Ordinary bus service proxies

Each proxy is an ordinary service recipient registered through the existing
client SDK, with a compact stable service name. It introduces no recipient kind
or core role. Incoming message IDs and bounded content are committed before the
message is acknowledged, so reconnect can recognize a duplicate delivery.

Text, JSON-looking control requests and approval-looking replies remain
content. Neither their origin nor their wording grants lifecycle, owner or human
authority. Real-bus fixtures exercise this distinction with a sender and an
isolated daemon; they do not use the fleet service.

### Recovery example

If a broker disconnects after a fake child starts but before acknowledgement,
the next connection reconciles the existing execution. If ownership cannot be
established, the result stays `unknown` and reserves the slot; it does not spawn
another child to recover availability. Dirty workspace contents remain available
for inspection. These are fake-backend library checks, not instructions for
starting a production team.


## Daemon caller-attribution bridge

<Status id="teams.attribution-bridge" />

The bridge is an optional local metadata query. It does not launch a team or
replace lifecycle grants. `ControlService::open` retains the unavailable
attestor; an embedder can explicitly select
`ControlService::open_with_daemon_attribution` with
`DaemonAttributionConfig { query_socket, lifecycle_socket, expected_uid }`.
Owner and human decision channels keep their separate credentials.

The lifecycle handler duplicates its actual accepted Unix socket and passes the
duplicate to the daemon with `SCM_RIGHTS`. The daemon checks the original
socket's kernel peer and current session state. It never consumes, peeks at or
writes caller bytes, changes the original flags/timeouts, or shuts it down.
The scoped reply is bound to one request and caller context; it is not a token
or a grant. Query and response framing are bounded, and failed, contradictory,
expired or ambiguous evidence cannot become another principal.

Production qualification is sealed and absent in this release. Configuring the
endpoint therefore returns unavailable; it is not a way to turn on attribution.
There is no sample qualification record, record loader or enable flag. Positive
fixtures use test-only eligibility facts with real processes and daemon state;
they are not proof that a deployed OS/runtime tuple is qualified.

The daemon exposes the endpoint only with `--executor-lifecycle-socket`.
`--executor-attribution-sock` overrides the query path and requires that option;
otherwise the query socket is `executor-attribution.sock` beside `agent.sock`.
Both paths must be distinct, absolute and private to the owner UID. These
options name sockets; they do not start a lifecycle server or install an
executor. See the [CLI reference](/reference/cli-and-mcp/#executor-attribution-socket).

### Identity and availability limits

Current exact principal/verb/target grants remain required. A known child needs
its own grant. The query refuses an unregistered caller whose current ancestry
reaches the querying executor before a session match. Re-parenting can escape
that intact-chain stop: future enablement must exclude deployments where any
process that can reap executor descendants is, or has in its current ancestry,
a principal matched by the resolver. This includes trusted Codex owners,
observed Antigravity entries, and foreign same-UID PID-namespace reapers. That
exclusion must remain true throughout enablement, not only during one test.

A shared Codex owner can select among roots it actually holds, with a matching
configured grant. Sibling roots under that owner are not isolated from one
another. Deliberate same-UID socket delegation or impersonation is outside the
isolation claim. On macOS, the socket PID can identify its last operator rather
than its connector; missing or contradictory evidence refuses attribution.

The query has four fixed workers and a two-second deadline. Partial clients
cannot create an unbounded worker queue. Same-UID code can occupy all four
slots, making attribution unavailable; ordinary messaging remains independent.
Expiry is checked again after the executor acquires its admission lock and at
the effect boundary.
