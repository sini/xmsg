`xmsg-executor` is a separate package in `extensions/executor/`. It now contains
an optional broker/supervisor entrypoint, ACP session mappings, a control journal
and operator commands. The default xmsg package does not install or start it.

**Runtime activation is unavailable.** Both caller and adapter qualification
remain empty/default-deny. There is no configuration flag, record loader or
sample record that enables a real harness. Fake subprocess and scratch-bus tests
exercise the mechanism; they do not qualify a model, platform or native effect.
See [teams](/concepts/teams/) for the boundary between the mechanism and a real pilot.

## Optional executor commands

These are commands of `xmsg-executor`, not subcommands of `xmsg`. Configuration
and socket arguments below must be absolute paths.

| Command | Meaning and limit |
| --- | --- |
| `check-config --config <file>` | Validate the bounded private owner configuration. Success prints `configuration valid; runtime activation unavailable`; it is not a qualification or launch check. |
| `serve --config <file>` | Bind the configured lifecycle, owner and human sockets and run the journal-backed broker. Missing qualification still refuses real lifecycle effects. |
| `call --config <file>` | Read one bounded strict `LifecycleCall` JSON object from stdin and send it on a fresh lifecycle connection. It sends no owner/human credential prefix or claimed principal. |
| `human --config <file> --session <id> --generation <N>` | Query genuine outstanding native requests through the human credential channel, then require explicit per-request confirmation on the controlling terminal. |
| `owner-disable --config <file> --expected-revision <N>` | Use the owner credential channel to persist an emergency-disable fence. Success does not confirm that native processes have stopped. There is no restore/enable command. |
| `content-mcp --socket <path>` | Stdio content sidecar for one owned execution socket. It exposes only text `list`, `send` and `reply`, not lifecycle management. |

The native runtime bootstrap is internal, not an operator activation interface.
There is no control-MCP facade: a shared MCP process is not proof of the agent
that issued a lifecycle call. The CLI-first facade preserves the actual kernel
peer for each connection.

`call` accepts `{ "request": { ... } }`, with optional `caller_context`. The
request has `version`, `request_id`, `verb`, `target`, `args` and optional
`deadline`. Caller context is only an accountable selector for an already
represented native session/root; it is not identity or qualification. Unknown
fields, caller-provided principals, role proofs and qualification record IDs are
refused. See the [non-activating example](/use-cases/#inspect-the-optional-executor-boundary).

## Owner configuration and qualification

`RuntimeConfig` version 1 separates these owner-selected settings from caller input:

- `control`: current grants, profiles and dispatch defaults. A template's optional
  `lifecycle_verbs` defaults to empty. Explicit delegation binds only its attested
  holder and exact new session/generation; current dispatch grant and template
  verb must remain present. Creation and parentage confer nothing.
- `paths`: the separate journal, lifecycle/owner/human sockets, attribution socket,
  runtime root and private owner/human credential-file references.
- `programs` and `workspaces`: fixed adapter/native executable paths and SHA256
  pins, arguments, native mode, immutable repository/base and approved root.
  Each configured pin has one unified provider/model to `native_model_id` mapping;
  actual native mode and model readback is required before prompting.
- `launch_environment`: a fixed search path and optional real account home.
  Configured home must match the current UID's canonical passwd home. It does not
  copy auth state or provide an arbitrary environment/credential map. Native
  executable overrides come from the pinned paths.
- `bus`: optional explicit node and agent/registration endpoints; absent by
  default. `auto_input: true` separately authorizes automatic content input.

The launch-settings digest is not proof of the native tool/hook/account settings.
Caller qualification and managed-adapter effects use separate records. The daemon
attests caller identity and call binding; executor caller qualification is an
extension policy fact, **not daemon-attested qualification**. A record for one
artifact, mode, host or policy revision confers nothing on another.

Missing caller scope, caller artifact evidence or protected-policy-store evidence
keeps effects disabled. Private mode bits and the same UID are not an isolation
guarantee. No request, adapter record or configuration field can supply the
missing trust property. A diagnostic receipt cannot restore an opaque caller
reference after restart. There is no old-PID re-query or silent replacement with
a newer record.

## Lifecycle, receipts and recovery

<Status id="teams.control-journal" />

The verbs are `dispatch`, `send`, `steer`, `interrupt`, `resume`, `stop`, `status`,
`result` and human-channel `approve`. Lifecycle calls need peer UID, per-call
attribution and current owner verb/target grants. Owner/human credentials do not
substitute for that attribution; no per-agent control credential is minted.

Authorization, durable admission, native submission and observed effect are
separate receipt layers. Replaying the same canonical principal/request ID
returns historical information, not fresh authority or another execution.
Different input under the same ID conflicts. Status/result identify provenance;
a finished ACP turn or a model saying “done” is not a verified completed task.

Strict steer addresses an active generation/turn. It neither starts a new turn
nor silently queues a prompt. Interrupt concerns the turn and never falls back
to session stop/kill. A failed or synthetic cancelled response leaves the turn
uncertain until independently qualified quiescence is observed. Silence and
background work without a structured ask do not become `needs_human`.

Reconnect observes the **same owned lease**, generation, native session and
transport epoch, rechecking caller and adapter eligibility before and after the
probe. It does not initialize a new session, replay a prompt or launch a
replacement. These paths are fake-tested, not qualified native capabilities.
`load_stored_conversation` remains unsupported without safe prior-retirement
proof; an ACP load mapping alone does not establish that proof.

A known failure before any execution row/spawn intent becomes a durable typed
`pre_launch_failure` with `failed` / `not_attempted`, audit and result. It is
excluded from broker selection and direct launch leases, so later work can
proceed without automatically retrying it. Post-spawn uncertainty remains
`unknown` and consumes its slot; a saved PID is not proof of ownership or death.
Stop preserves dirty/unowned workspaces and does not claim full descendant
absence merely because a direct child was reaped.

Before effects, current caller and adapter qualification, grant/profile,
generation/turn, policy, expiry, epoch and disable state are rechecked. Losing
eligibility stops new work, including queued input and reconnect/resume. Restart
does not clear emergency disable or resurrect stale authority. Inspection and
stop remain separately authorized; disabling does not undo an effect already
admitted or a bus message already sent.

## Supervisor and workspace boundary

<Status id="teams.supervisor" />

Only a journal-derived lease can launch an execution. An exclusive execution
lock and durable spawn intent precede the OS effect; receipts supplied by a
caller are not launch authority. Native startup and client I/O share an absolute
wall-time bound. Control polling and scheduling remain fair while native output
is buffered. The bootstrap channel is not inherited by the adapter.

Workspaces bind an owner-approved repository, immutable base and destination
root. Identity, HEAD and worktree inventory are revalidated before execution;
preparation does not copy dirty work or harness auth files. Dirty or unowned
workspaces are preserved on cleanup.

### Runtime socket location

The owner configuration's `paths.runtime_root` selects the short private parent
for per-execution sockets, separate from state and workspace paths. The entire
derived socket path is checked before execution-directory/workspace creation,
including its terminating NUL: macOS permits 104 bytes. An unsafe existing root
is refused, not chmodded or taken over. Choose a shorter private runtime root
when the typed error reports a path-capacity refusal; long state/workspace paths
are not silently relocated.

The internal `OwnerRuntimeConfig::for_user` library chooser prefers a validated
owner-private `XDG_RUNTIME_DIR` on Linux, or a short per-user directory under
canonical `/tmp` on macOS/Linux without that variable. This helper is not an
activation flag or a replacement for the CLI's explicit owner configuration.

## Human-only native requests

Only a genuine request in the driver's live outstanding-permission map can
create a native ask. The private journal binds its native RPC/operation,
session/generation/turn, transport epoch, digest, policy, expiry and once-only
options. Failed tool status, hard denial, messages and constructed events create
no ask. Interrupt intent invalidates asks immediately; late old-turn callbacks
cannot reopen them.

The human command reads only the configured separate human credential reference,
shows the bounded request as data on `/dev/tty`, and requires
`confirm <approval-id> <number>`. Choices are genuine allow-once/reject-once
options or cancellation. There is no `--yes`, persistent-allow or approval via
chat. Querying does not consume a request; recording a decision does not confirm
the native response effect. The actor rechecks all fences before responding.
This is a trusted operator-channel contract, not physical-human detection or
isolation from arbitrary same-UID code. Credentials never belong in prompts,
arguments, audit records or evidence.

## Managed content tools

<Status id="teams.supervisor" />

Each owned execution uses an ordinary SDK service proxy. The registration stays
in the supervisor process; a child MCP process cannot inherit that service
identity. The separate `content-mcp` sidecar advertises only text `list`, `send`
and `reply`. It has no `inbox`, `replies`, attachments, local-path reads,
`as_agent`, caller identity nonce, lifecycle, owner or approval operation.

Owner-enabled automatic input commits bounded content before bus ACK, then
creates an execution/generation/epoch-bound delivery intent. It does not fabricate
a lifecycle admission from the sender or interpret JSON/prose as control. There
is no competing inbox/pull consumer. Unknown transports retain queued content
without retargeting it to a replacement.

Each outgoing call has a fresh bounded policy check immediately before one SDK
forwarding admission. Later calls are denied after revocation or disable; an
already admitted in-flight call may finish. No journal lock is held across the
network wait, and stale authorization is not cached.

## Candidate pins and verification

| Harness | Adapter | Native runtime |
| --- | --- | --- |
| Claude | claude-agent-acp 0.108.0 | Claude 2.1.327 |
| Codex | codex-acp 2.7.0 | Codex 0.169.1 |
| Antigravity | native agy ACP | agy 1.5.10 |

These are a candidate ACP-v1 test matrix. **No real tuple is qualified.** Fake
fixtures do not prove steering, interrupt quiescence, native resume, human-only
provenance or reviewer isolation. Codex `humanCommand` provenance may be recorded
as unsupported for the narrow human-only row; it is never passed/retained or
usable by a caller requiring that capability. agy mappings remain unproved.

SAFE/human-only is the baseline. The future reviewer/overseer and UNSAFE
administration stages are not enabled here. Budgeting has two layers: an
owner-provisioned hard provider account/project cap and executor wall-clock/
content-byte limits. Byte limits are not token limits; no estimator fills that
gap. Adapter-native token enforcement is proved or unsupported per pin.

From a source checkout, developer checks need no real adapter/account:

```sh
extensions/executor/scripts/check.sh
```

This builds an explicit scratch daemon and runs the package's own executed
inventory/census, fake peers and OS subprocess controls. It is not a pilot or
qualification. A real pilot additionally needs reviewed immutable artifacts and
runtime envelope, protected caller policy, explicit account/model/time/token
bounds, no production secrets/data or external task targets, and observed
stop/cleanup behavior. A scratch repository alone is not isolation. Installing
xmsg does not install adapters or activate any of these records.

## Daemon caller-attribution bridge

<Status id="teams.attribution-bridge" />

The bridge is an optional local metadata query. It does not launch a team or
replace lifecycle grants. `ControlService::open` retains the unavailable
attestor; an embedder can explicitly select
`ControlService::open_with_daemon_attribution` with
`DaemonAttributionConfig { query_socket, lifecycle_socket, expected_uid }`.
Owner and human decision channels keep their separate credentials.

The lifecycle handler duplicates its actual accepted Unix socket and passes the
duplicate to the daemon with `SCM_RIGHTS`. The daemon checks the original
socket's kernel peer and current session state. It never consumes, peeks at or
writes caller bytes, changes the original flags/timeouts, or shuts it down.
The scoped reply is bound to one request and caller context; it is not a token
or a grant. Query and response framing are bounded, and failed, contradictory,
expired or ambiguous evidence cannot become another principal.

Production qualification is sealed and absent in this release. Configuring the
endpoint therefore returns unavailable; it is not a way to turn on attribution.
There is no sample qualification record, record loader or enable flag. Positive
fixtures use test-only eligibility facts with real processes and daemon state;
they are not proof that a deployed OS/runtime tuple is qualified.

The daemon exposes the endpoint only with `--executor-lifecycle-socket`.
`--executor-attribution-sock` overrides the query path and requires that option;
otherwise the query socket is `executor-attribution.sock` beside `agent.sock`.
Both paths must be distinct, absolute and private to the owner UID. These
options name sockets; they do not start a lifecycle server or install an
executor. See the [CLI reference](/reference/cli-and-mcp/#executor-attribution-socket).

### Identity and availability limits

Current exact principal/verb/target grants remain required. A known child needs
its own grant. The query refuses an unregistered caller whose current ancestry
reaches the querying executor before a session match. Re-parenting can escape
that intact-chain stop: future enablement must exclude deployments where any
process that can reap executor descendants is, or has in its current ancestry,
a principal matched by the resolver. This includes trusted Codex owners,
observed Antigravity entries, and foreign same-UID PID-namespace reapers. That
exclusion must remain true throughout enablement, not only during one test.

**macOS qualification** <Status id="teams.attribution-bridge" />

The Darwin receiver checks ancillary framing with a bounded peek before
consuming query or reply bytes. The daemon's delivery spawn allows only
explicitly mapped descriptors at exec. Production attribution stays
unavailable until the exact OS, kernel and runtime tuple qualifies. A passing
CI fixture does not qualify an operator's Mac.

A shared Codex owner can select among roots it actually holds, with a matching
configured grant. Sibling roots under that owner are not isolated from one
another. Deliberate same-UID socket delegation or impersonation is outside the
isolation claim. On macOS, the socket PID can identify its last operator rather
than its connector; missing or contradictory evidence refuses attribution.

The query has four fixed workers and a two-second deadline. Partial clients
cannot create an unbounded worker queue. Same-UID code can occupy all four
slots, making attribution unavailable; ordinary messaging remains independent.
Expiry is checked again after the executor acquires its admission lock and at
the effect boundary.
